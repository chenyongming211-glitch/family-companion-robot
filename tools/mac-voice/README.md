# MacBook 连续语音测试

页面只有一个“开始说话”按钮，模拟手表唤醒。点一次后持续收音，说完自动回答；助手播放时直接开口，自动停旧回复并回答新问题。活动时同一按钮变为“结束对话”，可主动回待机。

Mac只运行浏览器与SSH转发，模型和语音服务在服务器；旧8000不切换。Chrome与当前Codex内嵌浏览器页面均可使用，麦克风权限分别管理。

## 打开

在Mac终端运行，或在Finder双击`open.command`：

```sh
./tools/mac-voice/open.command
```

使用自己的SSH授权。保持终端窗口开启；按回车关闭这次隧道。仅绑定Mac的127.0.0.1:18010；端口占用可用`VOICE_LOCAL_PORT=18011 ./tools/mac-voice/open.command`。

脚本在服务器读取专用客户端令牌，通过SSH领取120秒一次性链接并打开Chrome。页面立即清除URL fragment，换900秒HttpOnly/SameSite cookie，校验loopback Host/Origin。模型Key和长期令牌留在服务器。刷新或配对过期后重新运行入口，不分享临时链接。

## 直接这样试

1. 点一次“开始说话”，允许麦克风。说“一加一等于几”，说完停顿，等待自动回答。
2. 接着直接问“二加三等于几”，不再点按钮。
3. 让它“从一数到五十”，听到数数时直接开口问新问题。检查旧声音是否停下、新问题是否得到回答，再接着说下一句。
4. 测试结束可点同一按钮“结束对话”。切换页面到后台也会释放麦克风。

唤醒期间麦克风一直发往服务器，包括助手说话时；服务器VAD只将检测到的发言交云端ASR，静音不触发识别。浏览器请求回声消除/降噪，页面显示实际设置。Mac扬声器回声、漏识别和误打断需现场确认；这不代表ESP-SR或手表AEC已验收。

## 限制和记录

- 空闲60秒自动回待机；连续单次讲话达到25秒、本次8个生成轮次或15分钟上限也会结束唤醒。页面显示预算/结束原因；配对仍有效时可再点一次唤醒，不自动续接/重发付费问题。
- 录音、转写与回答不写本地文件或localStorage，正文仅在当前页面显示；服务器只保存无正文的阶段/usage/会话元数据。
- 播放位置由浏览器输出时钟估算，无可用时钟时为unknown。服务器输入首帧至audio.cancel延迟、页面执行stop耗时，都不能冒充物理扬声器停声时间。
- 当前是连续问答和自动插话；故事原稿的准确接续、Go工具/记录、手表接入仍分别验收。
