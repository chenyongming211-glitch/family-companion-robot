## 五位成员的真实采集步骤

目前没有用户提供、可核查的新机器人录音清单，机器人登记→机器人查询、手机原始登记→机器人查询均为 `not_run / awaiting_recordings`。以下是待执行操作表，没有完成产品登记界面，也没有自动开麦。

1. 为五位成员分配私有代号 M01–M05；另招至少二十位不在两组登记中的陌生人 U01–U20。征得录音同意后再由操作者手动开始。姓名、音频和身份对应只保存在私有云端清单。
2. 先冻结真实设备型号、机器人与手机原始采集入口、日期 / 会话 ID、采样格式、距离、朝向、环境、现有 VAD / AEC / 降噪链、转换命令及版本。保留原始采样率和转换后 SHA；没有转换则写“无”。手机必须直接录人声，不能播放手机扬声器再录给机器人。
3. 同一位成员分别用机器人麦克风和手机原始麦克风登记多句不同内容，正常音量说话，避免他人插话。每条件目标约 20 秒有效语音；同时记录原录音秒数和既有 VAD 估计有效秒数。不能用本报告的 20 秒公开原录音合同替代真实有效量目标。
4. 每段记录长度、RMS / 能量、有效人声量及登记内部一致性诊断。先按预先固定规则判断，再形成模板。登记一致性只使用登记内部信息，不能参考查询成绩；诊断提示不能保证认定混人。
5. 登记完成后另开查询会话。每位至少二十句新内容、至少两次采集，建议 S1 的 Q01–Q10、S2 的 Q11–Q20。两次均与登记会话、内容及源组隔离。每句独立决策；不靠后一句纠正前一句，不使用查询积累。
6. 同一批新的机器人查询分别对两组独立模板评估：A 为机器人登记，B 为手机原始录音登记。两组不融合；工作点只由独立开发集按原 B 助手、陌生经验目标 0.01 和 margin 网格 `[0, 0.01, 0.030229, 0.05, 0.1]` 选定并冻结，不从最终验收回调。
7. 陌生人每位至少十句机器人现场新录音，共至少 200 句，均保持访客。先冻结完整验收输入、来源和角色，再开始一次评估；不因结果换人、换段、改阈值或挑选补录。
