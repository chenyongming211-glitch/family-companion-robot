# 跨会话记忆按关联使用：实现与验证

日期：2026-11-17。代码 `8f8664a`、`041a243`、`7b0477c`；设计编排补充 `5a6b621`。本批只处理记忆使用方式，B语音合成失败另留待查。

## 起因和实现

用户现场反馈 A/C 故事仅开场便进入聆听，B无声。对应 A/C 两轮都是模型生成同样37字、设备全部 played；新终态记录为 completed，原因未提供。隔离带原跨会话资料可复现37字；仅在测试请求里去掉旧资料后为150字完整故事。支持历史影响的线索，不声称已确定模型内部原因。此前仅补一句故事提示未通过现场测试。

现在当前会话已播上下文持续保留，旧会话原话不再无条件合并。共用无声选择器按当前请求/当前已播背景，从现有有界候选里选择至多3条必要证据，结果仅 none/recall/continue；不能执行硬件操作、删除记忆或直接发声。普通新故事不能只因旧话题相似就套用旧回答。A/B/C共用，未增加关键词意图规则。

存储仍为当前鉴权设备最近7天、最多24轮；选择候选沿用最近8条/6000字及最多6条短摘录的投影，总候选至多14，非全部档案。只有选中的原话及时间/来源/播放边界进入主回答背景；未选数据继续保留。当前会话用于选择的投影较短，主回答仍保留原有最近24轮上下文和真实播放证据。播放完整不代表故事任务完成。

保持原音乐分类顺序：音乐规划仅收当前会话背景；普通回答在分类后选择旧资料并取得真实持久化保存回执，再进入剩余规划与回答。私人音乐窗口/媒体排除保持；已由音乐流程处理的操作不新增记忆选择请求。握手后复用现有权限刷新，撤权背景在提交前移除。清除时递增代次（包括删除失败/未知），网络返回、最终提示与准备中的提示刷新均重新校验，迟到选择不复活旧资料。

有旧候选时新增一次至多3秒的模型请求，含连接/提交/终态；没有候选、转写不可用或明确清除时跳过。失败/超时保留当前上下文、略过跨会话资料继续正常回答，不假称历史不存在或已删除。新请求独立保存计数、耗时和受控用量；缺少提供方用量保持 unknown，不复制任意提供方正文或错误信息。
