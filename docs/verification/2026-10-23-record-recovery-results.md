# 文字记录与恢复实施验证（2026-10-23）

本轮按“先记录与恢复，同期离线定位，再决定自动接续”的顺序实施。自研 Go 网关保留；没有改手表固件，没有迁移框架，没有在生产加入辅助 ASR。准确文字位置仍为 unknown，未知时继续询问起点。

## 实现范围

- 已鉴权设备 MAC 规范化后隔离快照，同设备同时仅一个连接；最后一次保存入队或清空完成前不释放设备租约。
- 本地异步原子文字快照，最多128条、每条512字符；恢复时网关注入最多12条近期文字。默认168h，可配置；单 worker 每分钟扫描空闲过期文件，清理还受磁盘可用性和排队影响。模型原生会话另外有其自身上下文，12条不是云端整个会话的消息总量。
- 保存输入、响应、会话/播放身份、时间与交付状态。生成、下发、设备数字播放完成、中断分别标记。中断草稿不作为已播文字注入模型。
- 原任务、终点、最新请求、用户选定起点来源和等待选择状态跨连接/进程恢复；新连接分配新身份。旧采样只显示为 historical_playback，当前 position_known=false、played_samples=null、text_position=unknown。
- 放弃/替换/清空保留权威状态；历史文字不授予执行资格，唤醒不会自动执行旧任务。保存回执而非入队决定成功事实，事实变化经快照 ACK 再生成；失败加载不以空快照覆盖旧文件。
- 手动说“请清空本设备对话记录”。只接受当前真实转写的直接命令，排除否定/引用/假设/旧输入。清除网关缓存和存储，并异步换原生会话隔离旧上下文；成功确认来自实际删除回执。新输入和中断仍可处理。
- 网关不持久化录音；实时处理的有界 PCM 留在内存。清空当前会话不等于删除云供应商持久留存，不作供应商政策承诺。

## 清空缺陷的真实反例与修复依据

未发布候选 ce51efa 已通过 Go 检查，但真实接口暴露问题：合成语音要求记住“青铜海鸥”→清空→模型确认清空成功→同一设备 WebSocket 再问暗号，仍回复“青铜海鸥”。本地文件已删除，活跃原生会话却仍含旧内容，随后可把旧内容再次写回。这与云厂商长期留存政策是不同的问题，不能靠更新 instructions 解决。

修复包括持久化关闭时的旧 parent transcript 抑制、原生会话更换、旧代事件退休、握手期间有界缓存新输入、实际删除回执控制确认、确认音频不形成可恢复业务任务。并补充清空期间新输入、清空确认被打断、重复工具调用、旧响应ID和迟到结果等回归。

当前千问后端另有以下真实能力探针，均为隔离会话和合成文本，无麦克风、设备播放或生产改动：

| 操作 | 实际结果 |
|---|---|
| 人工创建 function_call 再提交 matching output | function_call item创建获确认，但output报 Unknown function call id；没有采用该方案 |
| 仅在新会话给当前清空请求与成功事实 | 模型仍调用清空工具，0音频；不能靠提示词避免重复执行 |
| session 或 response 的 tool_choice=none | 本次后端仍调用清空工具；不依赖这一字段 |
| 显式 tools=[]，再提交请求与真实成功事实 | 0工具调用，语音“已清空本设备上的对话记录。” |
| 显式 tools=[]，真实失败事实 | 0工具调用，明确“存储出错，未能成功” |
| 已注册工具后再动态 session.update tools=[]并等ACK | 0调用，正常成功确认；支持采用同一 ACK 流切换工具集 |

最终实现确认阶段显式空工具集，下一条正常业务恢复实际可用工具并等待其 ACK；另有本地操作去重，防止同一清空命令被重复执行。以上能力是本次所用 qwen3.8-omni-flash-realtime 后端的观测，不概括所有版本。

## 断点与后续门槛

已实际运行83次离线推理：30次Qwen强制对齐、30次独立Whisper tiny、23次Qwen3-ASR纯文字。构造片段边界、实际识别与资源记录见[对照报告](2026-10-23-record-recovery-alignment.md)。较强中文ASR改善本组有声文字匹配，但静音有“嗯”幻觉；纯文字匹配与时间戳都不能直接证明声音已完整播放。

保守策略在有限构造样本可推进部分前缀并重读边缘片段；未建立自然连续语流的独立声学边界真值，也未标定同一播放身份的源PCM→编解码/重采样/队列→设备I2S坐标。因此不启用自动准确接续，不把保存完整对话等同于已知最后一个播完的字。
