# 网关唤醒来源修复

## 实现与边界

来源依据改为设备输入阶段与上游commit身份，不再比较ASR与唤醒词文字。首次listen.start之前的缓存先切manual分段，再转发原始音频；detect触发一次显式commit。其ACK的非空itemID绑定wake来源，迟到转写只补文字。ACK与首次start到齐后创建一次问候，在response.created后恢复VAD并转发等待中的业务PCM。

没有缓存的detect、会话中的detect不接管下一条输入；包含唤醒词的真实业务语音仍可成为暂停任务。业务排队上限64000字节，与16kHz/mono/PCM16两秒重放窗口相同；8秒未完成交接或队列超限均关闭会话，不能静默截断。manual按键模式优先保留用户采集，不生成自动问候；交接期间的stop在完整转发后提交业务输入。上游重连永久结束该设备连接的首次唤醒捕获资格。

此契约将设备检测前缓存作为wake阶段，保护start之后的业务输入，不承诺切分完全落在同一检测前缓存中的任意业务句子。未新增辅助ASR、过滤/替换音频或修改正式提示词。

## 确定性验证

新增WebSocket/Opus集成回归先在旧代码看到预期失败，再实现修复。覆盖“小志”“小知啊”“任意转写”、ACK先于/晚于start、迟到STT与STT先于ACK、同一ACK重复、匿名ACK拒绝、无缓存detect、manual延迟stop、超限和8秒超时。

额外覆盖真实交接链：33个不同噪声帧，共63360字节业务PCM，在唤醒交接中排队；分别注入speech_started先到及response.done/cancelled先到，比较重连后重放字节完全一致，并确认下一帧没有重复。这是无声合成协议回归，不是板上收音测试。

旧文字相等排除测试已替换为输入身份契约。部分旧fake在未发送listen.start前直接发业务VAD/response；接受这些业务事件会结束首次捕获资格，保留旧客户端和现有工具取消行为，而不是把后续音频误作缓存。

## 实际千问与模式约束

第一版隔离真调用暴露provider限制：`turn_detection.silence_duration_ms cannot change after audio append`。旧SetMode会重发阈值和静音时长，在关闭再开启VAD时遭拒。新增序列化回归先RED再GREEN，改为仅切换type/null；完整VAD参数仍只在Open配置。

独立静音探针确认实际配置：初始semantic_vad/threshold0.5/silence600ms→null→仅semantic_vad，恢复后silence为provider默认800ms，**并非保留600ms**。该差异已明确记录，没有声称模式切换完全保留原参数。

Linux候选v2的真实模型测试保持qwen3.8-omni-flash-realtime、Tina及正式提示词，只用机器合成WAV：

| 场景 | 结果 |
| --- | --- |
| 正常唤醒后完整数到50 | 唤醒转写“小志”，问候正常，完整1–50生成/传输554帧 |
| 问候中发数数指令，再在数数约5秒时直接插话 | 同样转写“小志”；问候被打断，网关跳过wake暂停；数数中断后保留playback2，数学回答2 |
| 随后查询原请求 | 明确回复“从一完整数到五十，每个数字都读出来，不要省略”，与网关暂停记录一致 |
| 继续任务 | 仍从46继续到50；准确继续位置未通过，不能把原请求修复当作位置映射已修复 |

插话入队至网关stop约809ms，含驱动排队/VAD/网络，不是实际喇叭停声。模拟回报按收到的帧计数，虽然遵循字段协议，不能称为I2S确认或用户实际听到的位置。
