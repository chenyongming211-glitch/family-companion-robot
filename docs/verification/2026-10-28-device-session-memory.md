# 同设备跨会话记忆第一期验证

日期：2026-10-28。运行与模型测试全部在云端；本轮没有在Mac启动语音服务，没有刷机、使用实体设备或自动发声。

## 范围

- Go18040/18041按鉴权device_id恢复最近7天、最多24轮的有界文字记忆。每轮最多512字用户转写、1024字有播放证据的助手文字；总量24000字。提供给模型的原话与早期摘录也单独限额。
- 复用internal/recordstore的私有快照、队列、落盘回执和期限清理。原始时间保留，重连不续期；无归属的旧客户端不启用，不从原始日志或旧网关回填。
- “清除聊天记忆”清除当前设备的恢复上下文；当前会话也过滤清除点之前内容。原始文字日志保留，其他设备不受影响；新对话继续记忆。
- 普通回答和澄清由原语音模型自然生成，无固定兜底语音、额外摘要模型或三段式产品调用。清除使用有界的完整语音命令识别；不是一般问题的关键词拦截。

## 真实模型与模拟播放

使用服务器现有模型配置、真实输入转写/原生语音生成，模拟小智鉴权、MCP及按音频时长推进的播放回报。没有接触实体扬声器、屏幕、麦克风或I2S。

- A告知“暗号是蓝色风筝”，模型确认；A关闭后重新连接，回答“上次的暗号是蓝色风筝”。
- B没有A记录，回答没有找到之前的暗号记录并自然询问，没有拿到A的暗号。
- A说“清除聊天记忆”，服务器记录verified_cleared，保存空快照并回读核实；随后询问暗号及服务重启后再问，均没有恢复旧暗号，模型自然询问线索。
- 最后自然表达复验的清除回答为“聊天记忆已经清除了”，没有宣称原始日志已删除，也不朗读回读/核实等后台术语。
- `real-story-final`：A原讲小兔子“跳跳”用长耳朵救气球；A重连后沿用跳跳，讲洪水中运送食物和绳子；服务重启后再续讲，衔接洪水退去后的情节。只证明本组语义续讲，不证明逐字原稿或精确字词停点。
- `compat-smoke-final`：模拟A音量40→20，回读核实；B保持音量60/亮度90且无设置操作。
- `compat-search-final`：同轮音量35核实＋实际native_search完成count=1并返回来源。来源混合当日/历史页，只证明搜索接线，不证明天气实况准确。
- `compat-barge-final`：故事播放中插入音量25，旧音频排空、新设置核实并完成新回复，B不变。

## 无效与失败证据保留

`real-memory-1`使用通用Realtime模型“朗读”合成输入，模型实际改写了提问、甚至生成答案；该轮只证明传输/模拟播放，不记为记忆验收。后来改用专用qwen3-tts-flash-realtime生成输入音频，当前产品仍由原生Realtime回复，未引入TTS作为产品链路。

`real-memory-2`的多分句素材被VAD分为多轮，只完成了后一个问题；无记录的B还编出了其他故事人物。没有把它标成完整通过。缩短为单一提问，并加强“历史问题没有对应记录时自然询问、不编值”的提示；不增加输出硬拦截。`real-memory-3`、`real-memory-final`和后续自然表达/冻结复验使用正确单问素材。提示约束不等于任意措辞下绝无幻觉。
