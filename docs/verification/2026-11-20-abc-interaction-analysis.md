## Go 实现评审与修复顺序（发布前评审）

复核时，运行进程的二进制摘要与正式版 `tts-20261120-r1` 的封存记录一致。三条产品链路共用会话、输入监听、音频编码、播放窗口和设备回执，各自负责生成回答。这些边界适合继续沿用。由 Go 控制同一轮的取消和播放状态，可让三路在切换、打断和续聊时遵守相同规则。优先调整共用监听取消播放的条件，以及 A/B 将合成结果交给播放器的时机。

### 1. 让正式版说清楚每一次停播，再处理 B 的已知输入错误

在现有输入事件和取消日志补录触发来源、输入与输出编号、播放参考是否可用、文字是否匹配、I²S 进度及回执年龄，覆盖暂缓、拒绝和实际取消。每次停播应能区分按键、识别预览、终稿和生成失败。通过结构化字段解释决定，无需保存原音或转写正文。仓库有开头匹配快照，正式版没有，按线上实际源码移植需要的字段。先留一组沿用原判断规则的基线。

B 的第二版候选作为独立修补。保留模型完整原稿，在 A/B 合成和回声比较之间复用实际送往合成的文字，覆盖表情开头、句内表情和连续省略号。以后的播放进度仍取设备回执，合成文本只作比对参考。云端用先前失败样本回归，微雪测试 B 自我介绍和长故事，核对第一包、最后一句和完整播放回执。

### 2. 修共用打断判定，先在 C 复验

在现有 `pendingInput` 内区分收到预览和确认打断。播放中的短预览来源存疑时允许旧回答继续，保存该输入与开始时输出轮次的关联。同一输入的新内容到达时重新判断。重复的识别、最终文本和等待时间本身都不能证明有人开口。终稿也经过同一判断，避免刚放过一次预览，又因为同一段回灌产生新回答或写入记忆。确有新问题时可以提前停播，无需说指定口令。显式按键立即停止。新一轮、断开或取消后淘汰旧候选，迟到事件不能停止新回答。

在同一位置固定音量与语料，先测无人说话，再测只说“停”、说“等等”和直接换问题，分别覆盖开头和中段。记录无人误停次数、真人成功打断次数、开口到实际停声的时间。另用静音和两档外放音量定位声源。如果文本对照仍无法区分，采集同时间轴上播放参考、麦克风和 AEC 后上行的能量、相关性、削顶和相对延迟。根据测量决定是否改微雪采集或 AEC。保留疑似回声之外的真人短词、正常按键和同会话续讲。

### 3. A/B 按验证完成的合成段交付音频

在共用合成循环增加产品用的逐段交付入口，兼容原有整轮返回调用。模型先给出完整回答，第一个合成段通过音频、原文、时间戳和终态检查后即可送入现有播放器。设备播前一段时，后台顺序合成下一段。继续使用原有流控、每轮时长上限和每段计量。同一轮里只维护一份原稿；现有文本事件会覆盖旧值，逐段发单句会使聊天档案只剩最后一句。

先用可控的第二段阻塞证明首段已经下发。再注入后段失败、真人打断和断连，核对不会重播首段或发出迟到音频。部分失败走现有取消和排空流程，已播范围以设备回执为准，失败尾段不能标为已播或作为已说内容写入记忆。微雪再验首音、句间停顿和最后一句，A/B 各测一次正常长回答和一次中途插话。

### 4. 单独优化回答前的等待

用相同设备和语料，分别测新故事、本轮续讲、跨会话回忆和真实设备控制。记录话尾、各前置步骤开始与结束、主模型首音频、服务端首包和设备首次播放进度。表情选择已经异步。仓库里有默认关闭的纯控制规划并行候选，本次已核对正式 R1 源码没有该实现。根据阶段耗时选择一项独立工作做对照，同时比较首音和额外模型调用数。

先保住按关联选旧记忆、清除后失效、设备动作需要回执的行为。新故事单独检查有没有人物、行动和结局。若生成稿只有开头且微雪已经全部播完，继续查生成和所选上下文。只有生成完整而播放中途停止的样本才进入误打断或播放故障统计。
