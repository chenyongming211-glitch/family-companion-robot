# 当前 Go Realtime 设备语音控制验证

## 范围与状态

用户已批准将双设备阶段按本轮完成处理，继续当前对话设备的音量、屏幕亮度和状态查询。这里不把此前尚未完成的双实机声学/功耗项目补记通过；同房间两台互相接话、原M5暂停的音频恢复排查及微雪300秒关机均不在本次修改范围。

当前候选已完成最终规格/质量审查和云端验证，尚未部署新二进制、未刷固件、未改变实体设备设置。最新结果见文末“最终候选验证”；前面保留迭代失败证据。设计和实现步骤见[方案](../superpowers/specs/2026-10-27-realtime-device-controls-design.md)及[计划](../superpowers/plans/2026-10-27-realtime-device-controls.md)。

## 接线与边界

- 每个鉴权后的小智Session独占MCP Bridge和工具生命周期，只发送到自己的WebSocket。
- 复用原devicetools三种固定工具及参数、超时、设置后回读校验。未协商MCP和Mac维持原路径，能力由实际发现结果决定。
- 原生工具会话采用text-only、search=false；正常语音继续原模型/音色和search=true配置，工具结果以受控事实交给语音会话，避免搜索与工具冲突。
- ASR文字最多等待300ms；词命中只筛选候选，由模型判断本轮控制意图。普通聊天不调用工具模型。每轮工具调用至多8次，总时限18秒；相对操作要求当前对应字段的核实读取，设置后验证回读也可作为后续操作的当前值。
- 完整response.done和工具字段通过校验后才执行。取消、重复call_id、错误scope、迟到结果不能触发旧轮次续答，设置失败不自动重试。已下发操作不能假称撤销。
- 持久化请求事件先于MCP下发；日志失败则关闭会话阻止未发操作。记录只保存受控白名单、整数参数和过滤结果，不写设备原始网络信息或凭据。

## 真实模型＋模拟小智设备

根代理额外运行私有验收程序，使用真实当前模型、系统合成普通话输入、两个独立模拟小智MCP客户端和按60ms出队的模拟播放回报。程序启动私有httptest入口，不连接真实M5/微雪，不发出扬声器声音。模拟回报按生产协议声明i2s_dma只是受控测试输入，**没有实测I2S、麦克风、扬声器或真人听感**。所有合成音频、文字记录、helper与proof仅在ignored目录/服务器，不进入Git。

首轮8段输入实际exit0（`real-mock-151251`）：

| 场景 | 实际证据 |
| --- | --- |
| A绝对音量20 | 模拟值40→20，设置后回读verified，语音确认20% |
| B查询状态 | 返回音量60/亮度90，B无任何设置操作 |
| A相对调小 | 本轮先读取20，再设置10，回读verified |
| A关闭屏幕 | 亮度70→0，回读verified；不将亮度0称为电源关机 |
| A亮度30模拟拒绝 | 返回device_error/verified=false，不重试，亮度仍0；语音明确没调成功 |
| A音量35＋普通天气提问 | 音量调到35并回答天气，但没有检索完成/用量/来源事件，**此例不证明发生实际搜索** |
| A否定调节，仅问数学 | 没有任何MCP设置，回答5 |
| A普通三句话故事 | 路由not_candidate，不额外调用工具模型，正常完成播放 |

追加明确联网搜索（`real-search-151808`）实际exit0：音量35设置核实后，语音链路出现`native_search.completed`、count=1、strategy=agent及9条来源。证明本次实际检索可与控制共存，不代表来源时效筛选或天气数值准确性已验收；来源中仍含历史页面。

追加播放中插话控制（`real-barge-151835`）实际exit0：故事正在播放时输入音量25，旧语音sent=completed=12960、terminal=drained；新设置返回verified/volume25，新回复sent=completed=54720、terminal=played。B保持60/90且无设置操作。三组验收均未记录turn_error/input_failed/drain_timeout或播放边界不一致。

这几组有限样本中，普通故事从话尾到首包为1269/1432ms，控制/状态查询2098—2970ms，明确联网的混合请求3453ms。只描述这些合成输入样本，不能推出真人延迟分位数或普遍无退化。工具规划与执行需要额外步骤，后续真实听感单独确认。

## 补充语义探针发现的目标错误

在部分能力修正后的候选上，`final-smoke-153012`的当前设备音量20/B状态查询再次通过。`final-semantic-153031`先验证“解释声音小一点、不要真的调节”没有MCP调用；第二段ASR完整识别为“把旁边那一台设备的音量调到百分之八十，不要动当前这台。”。规划器仍调用device_set_volume80，模拟A从40变80，语音随后却说不能控制旁边设备并询问是否调整当前设备。验收程序因发现了实际模拟设置而超时失败，exit1。

这是有完整证据的目标授权缺口，不能归因于转写漏字，也不能因为语音最终拒绝就记为无副作用；仅提示词限制不足。未连接实体设备、未发布，原M5/微雪设置未被该探针改变。已暂停发布并补服务端目标范围检查：不支持目标或当前整台禁令必须在规划器/MCP之前拒绝执行，并保留自然语音解释。修复需不合作规划器的失败回归、中文/英文目标与否定范围测试及真实语义复验，再重新规格/质量审查。
