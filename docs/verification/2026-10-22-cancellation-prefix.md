# 千问取消先于 VAD 时丢失插话开头

用户暂不在现场，本轮仅使用本机合成中文语音，在服务器 `127.0.0.1:18022` 的隔离网关调用真实千问。没有操作手表、采集现场音频、打开 realtime 或修改正式服务。隔离实例使用独立测试 token 和虚拟设备 ID，有五分钟运行上限，测试结束后停止。

## 根因证据

诊断版 `b2ab6a0` 使用与线上相同的千问模型、音色和 `semantic_vad`。合成客户端按 60ms 上传真实 Opus，收到约三秒计数后直接上传“停一下，先告诉我一加一等于几”，没有再次发送 `listen.start` 或 `abort`。

- 实测先收到 `response.done` 的 `cancelled`，网关立即发送 `tts.stop reason:interrupted`；约 757ms 是客户端第一个有效合成语音帧到收到停播控制的时间，**不包含真实扬声器或手表**。
- 取消发生时旧连接已有未提交的输入。原代码在此路径调用 `interrupt(replay=false)`，清空 `inputTail` 后重连，只有后续音频进入新连接。
- 新连接转写为“先告诉我一加一等于几”，缺少“停一下”；随后正常回答二。旧连接未在取消前报告 `speech_started`，新代次后才有该事件。不能假定取消与 VAD 的到达顺序固定。

这是隔离测试确认的网关丢句首缺陷；它不证明此前录像中未及时停播也由这个缺陷导致。实机仍需核实播放期上行、千问 VAD 和设备执行。

## 最小修复与回归

仅对 auto/realtime 中的 `response.done/cancelled` 复用现有有界重放路径：先下发停播、清空旧音频队列，再重建上游并重放尚未提交的最近两秒输入。已有 `speech_started` 路径不变；主动 abort、失败回复和 manual 取消仍丢弃旧输入。未修改 AEC、VAD 阈值、固件或硬件。

新增真实本地 WebSocket/Opus 回归，覆盖取消先到、VAD 先到、两秒上限、已提交输入排除、重放一次后继续接收新帧，以及失败/manual/主动 abort 不重放。停播必须早于被测试端故意阻塞的重连握手。旧代码的取消先到场景复现失败；修复后完整 macOS `go test -race -count=1 ./...` 与 `go vet ./...` 通过。macOS 链接器有既有 LC_DYSYMTAB 警告，测试退出码为零。

原始合成音频、结果、日志和构建证据位于私有 `artifacts/aec-away-probe-20261022/`，不进入 Git。
