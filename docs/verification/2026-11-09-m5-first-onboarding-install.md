## 认证切换与数据边界

## 安装与中断处理

一次写入前同连接重新核对ROM/MAC/16MiB/安全状态和新包、双备份、权威配置。持久写意图，最终stub WRITE_FLASH_ATTEMPTS=1、无force/自动重试/自动启动。22:35:08开始写16MiB，22:36:58写入摘要通过。

22:40完整回读遇SerialException，中继按保护停止，没有自动重刷。用户明确回复动过连接线或按键；同USB身份仍存在，但no-reset探测不再处于ROM。显式重新进入目标ROM后只读诊断：boot/table 0..0x9000及其余0xf000..16MiB的硬件MD5均匹配，仅NVS/OTA元数据已随首次运行变化。此时不以重新刷写强行恢复运行元数据。

实际小块NVS用官方解析器核验4页/2使用页、25有效条目、6 namespace，所有有效页/条目/数据CRC通过，原工厂七项值（含salt/verifier）与供应包及原NVS完全相同，activated=0，官方SRP验证通过。OTA0 seq1/VALID、另一sector全FF；整体8KiB摘要固定 `8ba3b110139f45443d4f268d1a3373ef99a1718b71d51664531b83ee2d4b91a3`。运行设置NVS摘要为 `62a7c16b9f40efeaf91d96b35b2778135dec046001a524bdbb661396ba86c964`。

只读恢复完整回读于22:55:36完成，16777216字节/482.6秒，SHA256 `7eb7b67843714a509e695bea6d2283b1250bfc83d32d3914f76c464436b8e57c`。全部非NVS/OTA字节与原预期相同；运行元数据、工厂七项、activated0、官方SRP及活动S3应用通过。运行后的整片与最初供应镜像不同，不记为两者逐字节相等。22:58:23及23:02:03的显式WDT仅启动/重开配网窗口，未再次写Flash。

初次手机扫描产生waiting任务，有两次BLE连接后由手机关闭，屏幕仍无设备码；用户报告“蓝牙响应超时，请重试”。切出微信时任务取消，回来后新建任务；没有IP/confirmed证据。缺少端点/API耗时，不能用断连后的NULL清理警告推断根因，也不能把正常180秒窗口结束当作首次超时原因。用户要求继续补齐M5实体屏幕码与现场排查，详见后续记录。
