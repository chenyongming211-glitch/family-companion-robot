# 声纹算法核查与选型依据（2026-11-05）

本报告接续[第一轮REA分析](2026-11-05-commercial-speaker-rea.md)。用户要求认真核查实际算法，不用推测替代选型证据。本轮进一步读取 Eagle 固定版本的模型文件、追踪原生模型读取／循环单元／打分路径，检查厂商基准源码，并检查本项目实际 ERes2Net ONNX 图。

**结论收紧：Go＋sherpa-onnx＋ERes2Net-base＋多句约20秒登记目前是已有实测支持的对照基线，不是已证明的最终最优方案。Eagle 可以进入同条件比较，但尚未取得本项目识别实测。不能因为商用、模型较小、采用循环网络或保留均值长度，就认定它更准。** Go 是服务实现语言、sherpa-onnx 是推理运行时，真正影响效果的模型、采集通道、登记、片段选择和身份决策需要分别核查。

## 2. 这次取得的实际文件和结构

Eagle 官方固定提交仍为 `7a117318154cdbd4b729460f968351e0dab32b53`。新增读取同提交的 `lib/common/eagle_params.pv`，4,658,658字节，SHA-256 `d3bf50a993c95c7ab052bacf42a808169b0fd75992e57c4a237233b29d7cb635`；Git blob 长度／摘要与官方树中的记录匹配。

原生库仍是 `lib/linux/x86_64/libpv_eagle.so`，1,261,648字节，SHA-256 `1518547098b0d2f7e6d04b18483b214a32a5d67c6b56a8055d4cb21aae72e3d7`。两者均为 `3.0.0`，封装包版本为 `3.0.1`。以下结论限定于这些字节和已追踪路径。

模型不是 ONNX、GGUF 或 safetensors。REA 的通用模型头读取器明确返回 `unsupported_target`，未把该失败当作解析成功；随后根据原生读取函数的实际 `fread` 顺序，独立读取自定义格式。未加载厂商库、执行其识别代码或绕过 AccessKey。

### Eagle：从模型文件与原生路径确认的结构

| 环节 | 确认内容 | 主要证据 |
|---|---|---|
| 输入与片段 | 16000Hz，登记调用每帧512样本；此模型最短识别输入为32×512＝16384样本，即1.024秒 | 上次采样率／帧长函数；本次读取 `0x16300–0x16331` 到对象 `+0x18/+0x1c` 的配置，结合 `0x13cd2–0x13cd8` 的最短输入计算 |
| 声学前端 | 512样本窗、128样本步长、40维频带特征；可见窗函数、频域功率聚合、对数及特征标准化路径 | 模型偏移30／34／38；读取函数 `0x1638b–0x165e5`；特征处理入口 `0xfc70` 的前半段 |
| 循环结构 | 两组、每组6条循环层记录；每层状态维256，首层输入40，其余层输入256；两组按相反时间方向处理 | 文件偏移374起的12条记录；读取器 `0xe970`；层循环 `0x10243–0x102cd`；方向选择 `0xf981–0xf9a3` |
| 参数表示 | 每条记录有 `3h(h+d)` 字节矩阵和 `3h` 字节偏置；可见有符号字节权重与定点状态运算 | `0xe9c6–0xe9e5`、`0xea31–0xeab5`；整数矩阵计算路径含 `movsbl`、整数乘加 |
| 循环单元 | 结构符合输入／遗忘门耦合的 LSTM（CIFG）：两个 sigmoid 门、候选 tanh、互补门控制的状态更新，再以输出门乘 tanh 状态 | CPU路径 `0x22c90`、`0x22d30`，tanh helper `0x14c40`；互补项 `0x22fa0–0x22fbd`；再次 tanh `0x231f2` 和输出相乘 `0x23260–0x232b5` |
| 时间聚合与输出 | 可见时间维求和聚合、256×256投影、256维输出、L2归一化和片段向量累计 | `0xe118–0xe15d`、`0x105eb–0x108d9`；模型尾部维度256／256、投影标记1及65536个float32矩阵项 |
| 多段与匹配 | 单段向量归一化后求均值，登记／查询均值做内积，再作单调分段映射 | 上次已追踪的 `export` 和 `process`；本次补齐模型中三处分数映射参数的来源 |

“CIFG”是根据恢复的计算结构作的归类，不是厂商公开的模型名称；没有声称已完成每种CPU／GPU实现的逐位等价验证。只看“3个分块”不足以判定循环单元类型，本次还检查了两个状态、互补门、第二次非线性和输出相乘的计算链。

忽略定点缩放、截断和近似非线性的细节，该路径的状态更新结构可表达为：

```text
i = sigmoid(a_i), g = tanh(a_g), o = sigmoid(a_o)
c_new = (1 - i) * c_old + i * g
h_new = o * tanh(c_new)
```

原生 sigmoid 查表与 Q15 sigmoid 网格的最大差异小于2个整数单位；tanh helper 可追到 `2*sigmoid(2*x)-1` 的转换。这里只用读出的表值作数学检查，没有执行厂商神经网络。CIFG结构的通用定义可参考[原始LSTM变体研究](https://arxiv.org/abs/1503.04069)。

自定义格式读取按12条循环记录及投影矩阵遍历，结束位置恰好为4,658,658，等于整个文件长度。这证明所列布局的自洽性，**不等于完整模型已运行验证**；训练人物、损失函数、数据增强、训练域和不同设备上的真实泛化能力仍未知。1.024秒是接口输入长度约束，不是该时长下准确率的保证。

### 我们的模型：检查实际 ONNX，而非只看论文名称

云端现有 `eres2net.onnx` 的完整摘要与[资产锁](../../tools/speaker-lab/assets.lock.json)一致：39,593,761字节，SHA-256 `1a331345f04805badbb495c775a6ddffcdd1a732567d5ec8b3d5749e3c7a5e4b`。

按[官方ONNX protobuf定义](https://github.com/onnx/onnx/blob/v1.17.0/onnx/onnx.proto)静态读取图，确认：

- 输入为 `x: [N,T,80]`，输出为 `embedding: [动态批维,512]`。
- 图中有96个 `Conv`、16个 `Split`、29个 `Concat`，末端含时间统计相关 `ReduceMean`／`Sqrt` 和 `Gemm`；191个初始化张量均声明为float32。
- 元数据明确标注 `framework=3d-speaker`、`language=Chinese`、`sample_rate=16000`、`output_dim=512`、`normalize_samples=1`、`feature_normalize_type=global-mean`。
- 层名包含 `/conv1`、`/layer1/.../convs` 等，与ERes2Net卷积特征提取路线相符。未把公开论文的默认训练配置直接冒充此导出权重的训练履历。

[ERes2Net论文](https://arxiv.org/abs/2305.12838)说明局部／全局多尺度注意力融合的设计；这与“把多条登记录音求平均”是不同层次的融合。Eagle的循环编码器与此CNN编码器确有架构差异，**维度、参数文件大小或网络年代都不能单独决定谁更准**。Eagle完整运行内存和时延尚未测量，不能拿4.66MB文件大小直接替代内存指标。

## 3. 哪些差异值得比较，哪些不能被当成提升

### 保留均值长度并不自动更好

设各片段已归一化，登记均值为 `m_e=mean(u_i)`，查询均值为 `m_q=mean(v_j)`：

```text
Eagle所见映射前分数 = dot(m_e, m_q)
                       = 所有登记／查询片段配对余弦的平均
                       = norm(m_e) * norm(m_q) * cos(m_e, m_q)
```

B 的[登记融合代码](../../tools/speaker-lab/enrollment_study.go)最后再次归一化，并采用余弦匹配，会去掉均值长度。两者具有可确认的数学差别。长度能反映向量是否集中，但音素内容、设备差异、同一人的不同声态也会影响集中程度，不能直接称为身份可靠度。

因此，**撤回把“保留均值长度”当作优先改善识别的依据**；它只作为单项对照候选。现在B跨设备拒识多，没有证据证明额外用长度影响分数就能缓解拒识。重新校准后正负样本如何变化，必须实测。

### 分数映射不产生新的身份信息

模型偏移18／22／26的float32值约为0.23／0.37／0.46。原生加载器 `0x16346–0x16361` 将它们读到识别对象 `+0x24/+0x28/+0x2c`，与后面的分段映射操作对应；它们不是 `voice_threshold`。

可见映射把低值截到0、高值截到1，中间两段以0.5为连接点。单调映射在非截断区不会改变排序；端点截断还会制造同分。把余弦数值换成0～1的显示分数，不能凭此提高识别能力，更不能把0.9写成90%的正确概率。厂商三处参数也不适用于我们的ERes2Net分数空间。

### 片段选择是系统差异，需要完整分母

Eagle的内部片段处理可见对多帧人声分数求均值、与阈值比较，并比较相邻候选窗口（`0x3b69d–0x3b7b8`），比单纯RMS能量门槛复杂。但本轮没有测量它对我们音频的通过率，不能直接称为更优VAD。比较时必须将“人声不足／没有结果”计入拒识或覆盖损失，不能只看双方各自通过的音频。

## 5. 厂商公开基准为什么不能直接决定选型

本轮核查[厂商基准源码](https://github.com/Picovoice/speaker-recognition-benchmark/tree/c48845e6508ee3bd506fb72a1410394b2cc18b11)，固定源代码引用 `c48845e6508ee3bd506fb72a1410394b2cc18b11`，提交元数据日期2026-07-17。已下载8个源码／说明文件，核对Git blob和内容摘要，并重建根树摘要与提交声明相符；未下载其中的音频。

- `dataset.py` 的类别是 `alexa/computer/jarvis/smart mirror/snowboy/view glass`，按同一人物目录打乱录音，前若干条登记、余下识别；不是我们的普通话跨设备划分。
- `benchmark.py` 默认3条登记，把查询对本人分数作正对、对其他已登记者的分数作负对。没有单独的“未登记者人物”测试划分，配对EER不能直接当完整家庭候选池的陌生人误接纳率。
- `engine.py` 将 Eagle 登记量设为3个内部片段、人声阈值0.15，输入无结果时抛错；其他模型以拼接登记语音提特征。不能把这套登记／门禁差异当纯模型架构差异。
- README公开列过Eagle EER 0.18%。该数字不是本项目结果，也不是正确接纳率99.82%；本轮没有复现其原音频、历史分数和完整运行环境。

Eagle[产品声明](https://github.com/Picovoice/eagle/blob/7a117318154cdbd4b729460f968351e0dab32b53/README.md)是文本无关识别；上述限制针对这份基准的证据范围，不能反过来断言SDK只能识别固定唤醒词。

还发现 `metric.py` 逐样本排序累计FAR／FRR，没有将相同分数成组为可实现的阈值点。已在云端直接运行固定源码中的指标函数，使用其requirements指定的NumPy 2.3.5核查最小算例：

| 输入分数（纯数学数组，无声音） | 该函数输出EER | 含义 |
|---|---:|---|
| 正例 `[0.5]`，负例 `[0.5]` | 1.0 | 两个同分样本被排序拆开；实际阈值只能全部接纳或全部拒绝，按两端点线性插值的EER应为0.5 |
| 正例 `[0.9,0.8]`，负例 `[0.2,0.1]` | 0.0 | 分离算例通过 |
| 正例 `[0.8,0.6]`，负例 `[0.7,0.2]` | 0.5 | 交叉算例通过 |

这是对代码同分处理缺口的实证，**不证明公开0.18%的实际偏差有多大**；需要当时完整分数、版本和数据才能审计该值。同分可能使这类计算偏高或偏低，不能断言厂商结果一定被高估。后续对照使用我们已实现的成组同分统计并保留分数，不照抄这个指标实现。

## 6. 现在能作出的选择

1. **保留Go服务和隔离worker边界。** 本轮没有发现换服务语言能解决声纹效果的证据；Eagle若后续胜出，可通过官方C API接入Go worker，其`.pv`不是现有sherpa-onnx声纹模型的直接替换文件。
2. **保留B作为对照，不称为最终验收方案。** [同输入旧50人实验](../verification/2026-11-04-speakeropt.md)中，base长登记跨设备Top-1为94.81%，V2为84.42%；但Top-1不是正确接纳率，权重训练人物排除也未经独立审计。[更小的新人物验证](../verification/2026-11-05-speaker-backend.md)里B在PC条件仍12/14拒识，产品问题没有解决。现有证据支持它继续作基线，不能支持“已经足够好”。
3. **不凭结构相似或厂商宣传更换模型。** Eagle在此场景的效果仍是未知；不采用其固定数值、保留模长或循环架构作为已验证优化。
4. **下一次真正的选型对照只回答两个问题：Eagle完整SDK是否优于B；相同ERes2Net下，均值内积是否优于当前余弦。** 后者只隔离打分差异，不能冒充复刻Eagle整套模型。两项都需固定登记原音频、独立查询和设备条件，分别冻结开发集配置，在同一陌生人约束下比较正确接纳、误归、拒识、无结果比例和端到端时延。

Eagle比较应固定有效AccessKey、原生库／模型摘要和所有参数。人声阈值与身份阈值分别在开发集确定；不从最终测试结果反选参数。登记／查询音频清单和源录音去重保持一致，双方的内部片段数不同也要如实记录。已看过的50人及小规模人物数据只能作为开发／回归对照，不能再命名为新盲测；最后的模型更换结论还需要新的保留录音／会话和实际机器人采集验证。

**最终模型尚不能定案的具体缺口：当前未取得可用的云端Picovoice AccessKey配置，尚未执行Eagle的普通话同条件对照。项目已核查的服务配置中未发现该配置；已向用户请求在云端私有位置配置密钥并提供路径，无需发送密钥正文。** 核心代码恢复得更详细，也不能替代跨设备效果测量。若商业候选没有取得对照数据，只能报告未知，不能宣布B或Eagle是最终赢家。
