# 停止注册后的声纹产品分析（2026-11-05）

用户明确停止Eagle注册和厂商申请，改用REA分析现有产品。已有申请只保留未发送草稿，不发送邮件、不创建其他厂商账号。本轮不依赖Eagle AccessKey，继续使用云端隔离REA 6.8.0。取得发布程序、分析算法、合法试用可运行和本项目效果通过是不同状态。

Vosk[官方模型目录](https://alphacephei.com/vosk/models)单列`vosk-model-spk-0.4`，其效果栏为TBD；普通话ASR的字错率不能用作声纹识别率。Sensory[官方资料](https://sensory.com/llm-info/llm-info-speaker-verification/)说明两种声纹模式，但没有本项目同条件识别实测。

Vosk目标来自`vosk==0.3.45`官方PyPI元数据列出的Linux x86_64 wheel，7,173,758字节，SHA-256为`25e025093c4399d7278f543568ed8cc5460ac3a4bf48c23673ace1e25d26619f`。因直连较慢，同时通过清华PyPI镜像取得，镜像整包摘要与官方一致；随后直连下载也完成，两份原生库摘要一致。实际分析库`libvosk.so`为25,986,496字节，SHA-256为`85c4654de3acdeb99abab86eeb2a6e603927d37089597c0fcc33d8638dc2ccaf`。没有pip安装或调用目标库。

Vosk参照源码固定到`4ab9821510b488efb7740094714a130bd3545e90`（2026-10-15），4文件Git blob摘要逐一核对。**此源码提交不等于0.3.45发布库的已证明构建提交**；下表原生指令和源码参照分别标识，只对实际指令支持的行为作二进制结论。

Neurotechnology包通过官方HTTPS地址的ZIP目录及Range按需读取，提取时校验ZIP成员CRC，并记录实际长度和SHA-256。下载页面所列包长度与实际响应存在差异，保留两种记录；后续证据绑定实际取得成员摘要，不伪称已核对厂商独立发布的完整包摘要。

## 3. Vosk实际REA结果

执行REA的`inspect-native-exports`，以及`inspect-with-objdump ... disassemble --symbol ...`，分析`SpkModel`构造函数与`Recognizer::GetSpkVector`。导出表读取覆盖完整，共19,137条导出，无解析问题；这只表示导出表完整，不表示整个产品语义已恢复。反汇编两次命令均正常结束，输出未截断、目标摘要保持。使用GNU objdump后端，没有声称生成C反编译结果。

| 已核查行为 | 本版本原生指令锚点／参照 | 实际意义与边界 |
|---|---|---|
| 使用非静音帧，并要求足够帧数 | `GetSpkVector`起点`0x2b0da0`；`0x2b193d`调用`GetNonsilenceFrames`；`0x2b0f93`比较49，`jle`进入不输出分支 | 至少50帧才继续；这是最低有效性条件，不是达到该长度就能高准确识别 |
| 滑动窗口特征均值处理 | `0x2b0fde`打包常量低32位为300；`0x2b1035`调用`SlidingWindowCmn`；固定源码设置中心窗口／长度300 | 模型前端有配套处理，不能把这一参数直接加到ERes2Net前端 |
| 神经网络计算后再变换声纹 | `0x2b150e`调用`NnetComputer::Run`，`0x2b155d`取输出；`0x2b1700`调用`AddVec`，`0x2b173a`调用`AddMatVec` | 源码参照为减模型全局均值、乘模型配套变换矩阵；矩阵本身需与模型匹配，不能借用到其他声纹模型 |
| 结果做长度归一化 | `0x2b174a`调用`Norm`，`0x2b178b`调用`Scale`；源码参照为缩放到长度`sqrt(维数)` | 不应误写为一定单位长度；余弦会消去该常数尺度，也不是身份正确概率 |
| 匹配示例使用余弦距离；短句有局限 | 固定`python/example/test_speaker.py`明确计算`1-cosine`，提醒过短片段不可靠、超过4秒更合适 | 这是示例策略及提示，不是官方保证或本项目实测；未从示例阈值推导可部署门槛 |

本轮没有取得Vosk声纹权重或执行真人识别，没有恢复其完整训练配方。没有把ASR说话人自适应的i-vector与这里用于识人的x-vector混为一谈。其所见非静音帧选择依赖识别器路径，不能假设接入当前Go旁路时无需额外模型和工程工作。

## 4. 商用Voice Verification原生结果

实际库`libMegaMatcherIdClient.so`为14,924,096字节，SHA-256为`22abe6d11ccf5db666f54d85f744580c62b005126b8fe26798d6b55e18ad9d2f`。REA读出293条导出，并核查符号表及4个导出函数的汇编。库的大量内部函数没有有效名称；objdump显示的`NCoreOnStart+偏移`只是最近导出符号的位置注释，不能把它当作函数名。

REA的objdump封装支持按符号选择，不支持指定地址范围，且总输出有16MiB上限。为继续跟踪内部地址，另用**GNU objdump直接作有界地址范围补充**，每次保存命令、原库前后摘要、原始汇编及范围；不把这些补充伪称为REA原生C反编译。范围边缘不保证恰好是函数边界；以下只引用范围内已确认的指令。没有加载或执行目标库。

| 已确认内容 | 实际证据 | 结论与限制 |
|---|---|---|
| 外层输入与验证入口真实存在 | REA核查`MegaMatcherIdClientPushManualSoundBuffer`（`0xceaa0`）和`MegaMatcherIdClientVerify`（`0xcfcf0`）；固定包C示例先选麦克风、设置`mmidmVoice=1`后调用验证 | 可手动传入声音；这不是已经跑通SDK或证明它比B准确 |
| 声纹与人脸走不同采集路径 | `0x3bbd27`比较模态1，`0x3bbd50`调用`0x3b9150`；模态0进入`0x3baf30`。调用链来自验证入口`0xcfd3d → 0x3bdb10 → 0x3bbd20` | 实际沿声纹分支分析；初筛的`0x3baf30`已确认是人脸，原始范围记录保留更正，不作声纹证据 |
| 声纹处理有累积和分阶段重试 | `0x3b9398–0x3b93ca`累积块量并比较阶段目标；达到后创建声纹处理对象、调用内部处理；`0x3b94a8–0x3b94bc`调整目标后回到采集循环 | 所见链路并非每块声音都直接输出身份。尚未逐项核对累计量getter语义，不把常量3／10冒充可移植的最佳秒数 |
| 验证有独立匹配分数与工作点比较 | `0x3b983f`调用内部比较，`0x3b986d–0x3b9891`读取配置，`0x3b98a0–0x3b98bd`比较分数并转不同分支；C例程在成功后另取matching score | 数字不是正确身份概率；所见验证API是给定模板的1:1流程，不能把该门槛直接搬到ERes2Net或50人候选池 |
| 登记分支有跨候选核验线索 | 无参考模板分支`0x3b98c8`；`0x3b9930`与`0x3b9956`两次内部核验，`0x3b9963–0x3b996f`要求两个状态均为1才到`0x3ba25a`后续组合路径；否则释放／轮换候选再继续 | 可确认多候选检查／重试控制流；对象类型和比较函数语义未逐一完全恢复，因此不宣称已复刻厂商的完整同人一致性算法 |
| 检测数量与状态有独立分支，错误文字还涉及质量 | `0x3b94fc`后的返回值／数量检查，静态记录关联`NVoiceGetObjectCount`；`0x3b9513`单独引用声纹质量获取失败原因 | 不从通用`GetQualityThreshold`推断声纹门槛；对象全部字段及质量模型未恢复，错误字符串也不能当作完整质量算法 |

## 5. 对当前方案的结论

1. 可以继续实际分析其他发布产品，不需要继续推进Eagle注册。免注册开源SDK还提供了可运行候选，但本轮未新增准确率。
2. 当前Go隔离worker架构继续保留；ERes2Net-base多句约20秒登记仍是已有实测基线，不能因新库可下载就更换。
3. 已核查的Vosk实现把“有效语音足够”“模型前端／向量变换配套”“匹配距离”分开处理。跨设备差异也受到录音通道影响；Neurotechnology的采集要求明确承认这种影响。没有发现仅复制某个厂商阈值即可解决本项目问题的证据。
4. 后续最直接的受控问题仍是：实际机器人通道登记是否改善跨通道拒识；在确认同一人、无人声重叠的范围内，增加有效查询语音是否改善正确接纳。它们是待测假设，需要独立校准、陌生人约束、换人清空和等待时延核查。既有AS-Norm／QMF失败结果不因本轮研究而失效，不重跑旧数据后冒充新盲测。
5. 新增一项明确的候选实验：登记时对各段做同人一致性诊断，提示异常段重录，并与现有等权融合比较。商用库的多候选核验控制流提供了检查方向，但并未证明具体规则已还原或能提高本项目准确率；不先把它变成硬过滤。查询侧则分别报告单句与有界累计结果，不能靠更长等待掩盖时延，也不能将说话人切换后声音混入旧人模板。
