# Realtime输出ASR与实际播放位置：隔离实验

**Goal:** 在现有百炼账号和服务器上验证“机器人输出ASR字时间戳＋Mac实际播放回报＋新千问会话恢复背景”，不改变现有三个日常服务。
**Scope:** 用户已同意先测试旁路方案。本轮是实验探针，机器合成输入、真实千问/ASR、真实Mac CoreAudio；不启用真人录音、不引入LiveKit、不把ASR放到用户输入主路径，也不承诺固定原稿逐字恢复。
**Architecture:** 独立Python脚本生成一次千问故事音频，按Opus编码/解码后的相同样本时间轴旁路送Fun-ASR。临时回环18031通过SSH供无麦克风Mac探针播放；CoreAudio完成样本作为保守已播前缀。按稳定ASR字时间戳筛选并与生成稿校验，丢弃旧原生会话，恢复新会话只带已播前缀，再做插问/继续。源音频提前生成，因此只能测试有音频预备时的对齐与恢复，不能作为完整在线时延排名。

## 约束与证据

- 源码/脚本Git直接main；Python测试、依赖和模型调用均在云端已有环境；Mac仅构建运行无麦克风测试客户端。
- 原8000、18010、18020、18030及原生窗口均保持；临时入口测试后关闭，不覆盖日常配置。
- API Key只读服务器受保护配置；付费调用前落无正文intent，不自动重试未知结果。
- 时间戳来自识别估计，必须验证单调/范围、稳定最终结果和与生成稿前缀的一致性；不按时长百分比裁文字。不一致保持unknown，不编造已播内容。
- 只使用保守的完整播放包，Opus延迟以编码后解码样本为共同时间轴；不伪装I2S或物理声学测量。
- 记录ASR最终结果到达与打断回报的先后、额外等待、重建握手/新回复首PCM，费用usage单列；未测试的真人体验单列。
