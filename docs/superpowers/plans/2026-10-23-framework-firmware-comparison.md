# 实时框架与固件隔离对照

用户授权：同时验证 LiveKit、此前参考的千问官方 Qwen-Live-Harness、自研 Go 网关及手表固件。用户休息期间自主完成无需现场配合的测试。

## 约束

- 固定交互：唤醒一次，连续对话并可随时插话，空闲超时后待机。
- 直接使用 main；不创建分支或 worktree。
- 不播放声音，不要求现场操作，不刷机或重启手表；隔离服务不得占用正式端口或修改正式配置。
- 不加入辅助 ASR，不迁移正式框架。仅上传机器合成音频；密钥仅从服务器受保护环境读取，不输出、不进入测试记录或 Git。
- 严格区分源码分析、单元测试、真实模型调用、模拟播放与手表实际播放；不能将假 sink 的时间当成硬件播放确认。
- 所有失败都保留条件、固定版本及可重现方法；只对已复现根因实施最小修复。

## 实施与验收

1. 固定模型、音频格式、合成语音与各上游源码版本，确认生产状态。
2. LiveKit：验证现成插件能否实际连接当前千问原生实时接口，运行会话/取消/播放契约测试；若需要适配器，明确标识适配范围。
3. Qwen-Live-Harness：以官方核心在无声输出环境运行真实模型对话、连续上行、插话及继续任务；检验官方上下文与播放回报的实际行为。
4. 固件：对实际已刷 17bb1e0 重建源码运行 host/sanitizer 测试与故障注入，质疑唤醒缓存、事件次序、状态转换、回报、旧队列和并发；检查已有实机证据的局限。
5. Go：同一合成输入验证真实固件的缓存→detect→start 次序、重复唤醒、同音转写、连续静音、打断与暂停任务归属；对真实模型和确定性协议测试分别记录。
6. 汇总对照；对可证明缺陷形成失败回归，明确最小修复边界、独立审查和所需验证。保存可重复运行的无密钥测试和报告，提交并推送 main。

## 结果边界

本轮不能独立验收现场唤醒率、声学回声消除、喇叭实际停声时延或中文逐字播放位置。完整恢复任务必须保留原请求、终点与已确认播放边界，不能由生成稿末尾或时长比例冒充实际听到位置。
