# 预合成语气词池（先出声）

## 为什么换掉模型生成

上一版的开场白由模型现场生成，首包 0.6s，所以阈值只能设在 2.2s——1100ms 的正常轮触发不了它，触发时又已经太晚。**要填 0.5s 的空，只能用 0 延迟的音频。**

真人接话 0.2–0.5s。这是唯一能到那个量级的办法。

## 音色一致性：这是整个方案的前提

用户问的：预合成的语气词和模型生成的声音，是不是同一个人？不是的话会被当成两个人。

**结论：会一致，但必须满足三个条件，缺一项就换人。**

| 条件 | 为什么 |
|---|---|
| 同一条 realtime 接口 | 用 CosyVoice 那套 TTS（longanyang 等）是**另一个模型另一个 speaker**，名字像也不是一个人 |
| 同一个 `voice` 参数 | 音色由 session.update 的 `audio.output.voice` 决定 |
| 同一种 PCM 格式 | 24k s16le mono。**重采样会移调**，音高一变立刻听成另一个人——比音色本身更致命 |

实现上不是"尽量一致"，是构造保证：合成本身就走 `NewNative`，和生产回复**同一段代码**、同一个 `session.update`、同一个 voice 字段。

### 实测（2026-11-22，服务器）

同一句话、两种角色（正常助手 / 复读机），同连接同 voice：

```
answer    F0 中位 282.4Hz  p10-p90 175-353Hz  centroid 1674Hz  语音段RMS -20.6dBFS
repeated  F0 中位 258.1Hz  p10-p90 169-324Hz  centroid 1380Hz  语音段RMS -19.4dBFS
差        -24.3Hz(-8.6%)   分布几乎完全重叠      差 294Hz            差 1.2dB
```

F0 分布在同一个区间、响度差 1.2dB → 同一个人。换人（如男声）F0 会差 100Hz 以上、分布完全错开。
8.6% 的 F0 差是同一人不同句子的正常韵律波动，不是音色差。

第一版脚本拿"整句话"和"单音节嗯"比，报出 58Hz 差距——那是**文本差异**不是音色差异（鼻音能量集中在低频、没有辅音噪声）。控制文本变量后才得到上表。

## 两处会毁掉「同一个人」的工程细节

### 1. 电平（最容易被忽略）

初版按峰值归一到 -3dBFS，实测：

```
正文   峰值 -9.6dBFS   语音段 RMS -20.6dBFS
池子   峰值 -3.0dBFS   语音段 RMS  -9.3dBFS   ← 比正文响 11dB
```

短语气词能量集中、没有停顿拉低均值，**峰值相同 ≠ 响度相同**。听起来是"有人突然凑到耳边大声嗯了一声"——同一个嗓子也会被当成两个人。

修正：按**语音段 RMS** 归一（目标 -19dBFS，比正文高 1.6dB 保证可闻），峰值封顶 -9dBFS 防削波。

### 2. 时长与抢占粒度

`嗯` 只有 240ms，播完到正文还有 700ms 死寂，比不垫更怪。所以不是一个长句，是**一串短句**，段间靠文件尾部的 250ms 静音自然呼吸。

代价是正文必须能在段边界插进来，否则一个 1.5s 的长句会把 1.5s 到达的正文拖到 2.1s。

## 抢占：`prefaceGate`

池子和正文抢同一个 FIFO 通道的队首。用一把互斥锁消除"池子以为还该说、正文已经在写"的窗口：

- 池子每写一段前 `Lock` 检查 `answered`，写完整段 `Unlock`
- 正文首包 `Lock` → 置 `answered` → 写包 → `Unlock`

结果：**已排队的段照播，正文紧接其后，之后绝不追加**。池子最多领先一段，所以正文最多被拖一段（tier1 净语音 230–410ms）。

旧实现的 bug 正是反面：抢到队首后才开始生成，正文排在未出声的安抚后面，首包 2544ms。

## 时序（实测值推算）

按 `prefaceFireDelay=500ms`、tier 边界 1200/2600ms：

| 轮次类型 | 时间线 |
|---|---|
| 快轮 800ms | 0.5 不触发（正文已在路上）→ 0.8 正文 |
| 中位 1.1s | 0.5 `嗯`(240ms) → 0.74 段间静音 → 0.99 检查：正文 1.1 到 → **1.1 正文**，只多等约 0.15s |
| 记忆轮 2.7s | 0.5 `嗯` → 0.99 `我想想啊` → 2.0 再垫 → 2.7 正文接缝插入 |
| 搜索轮 6.1s | 0.5/1.0/1.5/2.6 依次垫 tier1→2→3，覆盖到 5s，6.1 正文 |

上限：总覆盖 5s、最多 6 段。之后静默——真人想久了也停。

## 音色可配置：不硬编码

这是用户明确要求的。池子如果固化成 `Tina`，后台把音色改成别的，机器人就会**用新音色回答、用旧音色清嗓子**。

所以：

- **目录按音色分**：`<root>/<voice>/manifest.json + *.pcm`
- **运行时合成**：缺这个音色的池子就现场生成（走 `NewNative`），完成后热替换，下一轮生效，不用重启
- **manifest 记 voice**，加载时校验：不匹配直接拒绝，宁可不垫话也不播错人的声音
- **文本清单独立于音色**：`LoadPrefaceLines(path)`，默认 15 条写在代码里，JSON 可整体替换（运营改文案不用发版）

`PrefaceStore` 按 voice 存池子，`Ensure` 做双检锁 + 每 voice 串行合成，避免并发重复生成。
voice 名做白名单校验（`[A-Za-z0-9._-]`），防路径穿越。

## 审计隔离

合成不是对话，不能污染生产记录。`Synthetic=true` + `MemoryOnly=true`：
- `Synthetic` 只给审计打标，**仍会写 intent 文件**（第一版就踩了，在源码目录掉出一堆 `live_preface_ack-*.json`）
- `MemoryOnly=true` 才真正不落盘

## 输出音频不进 ASR

`release()` 增加 `preface` 参数：池子音频**进回声参考**（喇叭确实播了，AEC 需要），**不进 output ASR**（那是"机器人说了什么"，垫话不是）。否则 `嗯` 会进 `turn.Tracker`，进而进记忆。

`resampler.Process` 无论如何都跑，保持跨包状态连续，只在 `asr.Feed` 前判断。

## 回滚

- 代码：`Preface=nil` 即完全不垫话（无模型兜底，故意如此——池子没加载要在日志里看得见，而不是静默退回 0.6s 生成）
- 部署：release 目录 + drop-in 按字母序，删最后一个 drop-in 即回到 r4
- 数据：`preface/<voice>/` 可整目录删除，下次启动重建
