# 松手调节和语音状态查询

用户明确要求：音量/亮度滑块松手即执行，移除下面的两个设置按钮，显示具体设置提示；每10一档小圆圈并易于整10定位。另报告说“现在的亮度和音量是多少？”时机器人回答无法获取。按此已给定交互直接实施。

小程序使用原生slider，范围0..100、step=10，changing只更新草稿，change在松手时一次提交归一化后的值。两条滑块均使用0、10…100共11个小圆刻度；刻度不拦截触摸，沿用现有紫色/半透明样式。显式区分设备当前读值与选择值。重复释放/正在处理/离线/无权限/无能力不产生额外请求，相同当前值无须下发。保留现有单命令、50秒观察、隐藏/退出/401隔离及真正confirmed回执才显示生效。反馈明确是音量或亮度，提交/等待/成功/失败均可辨识。

语音模型已存在device_get_status→self.get_device_status固定工具，设置也依赖读回核验。只读核对实际发布源码和用户这次对话元数据，定位查询失败的实际边界；只报告脱敏事件和数值，不把对话正文/凭据复制到Mac。若发现缺陷，先针对原话回归RED再做最小修正，查询不得触发设置。不得从历史或模型常识猜当前值。未复现时明确保留现场待验，不编造根因。

所有依赖、测试、构建、服务操作仍云端；Mac仅代码/Git及微信测试客户端。main直接提交推送；不新增依赖、不重构无关模块、不刷设备、不碰退货M5。若须改语音服务，仅基于当前实际部署源码合入必要文件，测试和来源核对后等无活动会话再切换。

2026-11-11用户跟进明确亮度“调大一点”漏判，已准备带字段限定的兼容补丁并通过测试；随后用户进一步讨论由模型结合上下文和反话识别意图，暂不将继续补词当作最终语义方案。当前部署与源码准备版分别记录，语义机制讨论见[方案](2026-11-11-contextual-device-control-design.md)。
