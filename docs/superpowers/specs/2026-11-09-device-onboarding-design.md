# 扫码添加设备与蓝牙配网设计

日期：2026-11-09。状态：用户已选择微信小程序＋蓝牙配网；本文记录具体设计，尚未实现、部署或完成手机/设备验证。用户提供的截图确认有小程序测试号AppID，正式账号尚未核实，HTTPS域名尚未提供。

## 1. 已确认目标与本次范围

用户希望新设备添加比手工登记MAC、配置设备凭据、再绑定家庭更简单，并明确选择微信小程序＋蓝牙配网。目标流程为：

**扫码打开小程序 → 登录并选择家庭 → 蓝牙配网 → 设备连接自有服务 → 自动完成家庭绑定 → 添加成功。**

小程序首期只承担新设备添加；登录复用已有家庭账号，不新增微信自动注册、手机号授权或另一套家庭身份。只有一个可添加设备的家庭时自动选中。家庭账号仍由现有管理流程供应，账号自助注册和邀请是另外的功能。

现有Vue 3管理平台继续承担设备、聊天和设置。小程序采用微信原生页面和TypeScript，不为少量配网页面另加跨端框架；业务权限由同一Go管理后端判断。支持微雪与M5的ESP32-S3，不恢复ESP32-C3支持。

本次设计包含可信设备供应、一次性认领、蓝牙配网及绑定完成条件。首期不增加设备转让、跨家庭共享、批量面向用户的导入、语音/模型调整、摄像头、支付或聊天小程序。

## 2. 当前代码与运行事实

- 上游固件`main/ota.cc`先读NVS的`wifi.ota_url`，为空时使用`CONFIG_OTA_URL`；上游Kconfig默认指向小智官方。启动响应的`websocket`字段随后写入NVS，语音连接读取其中的URL和token。因此Wi-Fi只提供网络，启动配置地址决定访问哪家服务。
- 本轮只读核对云端私有环境：当前启动接口下发`ws://82.156.48.111:18041/xiaozhi/v1/`。现有设备走自有Go语音服务。源码采用小智协议不代表使用小智官方云；清除启动地址后也不能假设上游默认值仍指向自有服务。
- `internal/gateway/server.go`的启动接口按私有路径和已登记MAC返回对应token；这不是面向消费者的注册接口，不能把“知道MAC或共享启动路径”当作新设备身份认证。
- `internal/deviceauth/registry.go`与`internal/realtimelive/xiaozhi_entry.go`目前启动时加载私有白名单，不动态注册；认证后的稳定设备身份由`internal/voiceidentity/store.go`维护。
- `internal/management/config.go`目前使用预配置账号、家庭、设备和绑定；正式管理服务只监听回环地址。网页绑定页仍是演示，没有真实认领写接口。
- 固件源码存在热点和BluFi配网分支；尚无已验证的微信小程序蓝牙客户端。不能将源码入口存在等同于两种手机、两种硬件均可配网。

以上是本轮源码/云端配置核对，不包含重新读取实体设备NVS或刷机。私有启动路径、token、MAC、Wi-Fi口令不写入本文。

## 3. 用户界面与成功条件

| 页面/步骤 | 用户操作 | 必须显示的结果 |
| --- | --- | --- |
| 扫码入口 | 扫描设备附带的小程序码，可选填写昵称 | 显示设备型号和“添加到我的家庭”；未登录时先登录，再回到同一添加任务 |
| 连接设备 | 允许蓝牙权限，按页面提示让设备进入配网状态 | 连接与二维码对应的设备，明确显示未找到、权限未开或连接失败 |
| 配置Wi-Fi | 选择设备扫描到的2.4GHz网络，输入密码 | 密码仅用于此次加密配网；已具备网络的设备可跳过输入密码，但仍须证明设备身份与本次持有 |
| 等待完成 | 等待设备联网及云端确认 | 分别显示“正在连接Wi-Fi”“正在连接服务”“正在绑定家庭”，失败停在对应步骤 |
| 添加成功 | 完成 | 服务端已持久保存本次有效绑定、所选昵称或默认名称，返回稳定device_id与实际绑定时间 |

手机请求已发送、蓝牙已写入、取得IP以及手机自报“在线”均不是绑定成功。成功必须由自有服务收到设备认证后的本次添加回执，并完成持久绑定。首次上电可自动进入有时限的配网窗口；以后由物理按键主动进入，正常对话时不常驻开放配网。

页面支持取消、重试与超时提示。退出清理本次扫描、蓝牙连接及密码内存；服务端过期认领不会占用设备。重试成功的同一任务返回原结果，不创建第二次绑定。

## 4. 二维码、身份与出厂准备

可信供应步骤在云端/受控生产流程完成：每台设备具备稳定标识、独立的设备认证凭据和一次性添加信息；生成与AppID对应的小程序码。后端保留可校验的设备及添加信息，不由消费者登记MAC，也不允许任何陌生MAC自助成为可信设备。

二维码携带不可猜测的一次性添加标识，后端将其映射到具体设备；不包含长期语音token、模型Key或Wi-Fi密码。该标识只用于首次认领，消耗后不能再次认领或转移设备。配网用的持有证明与长期云端设备凭据分离：基线采用随机128位的一次性添加标识作为首次配网的Security 2密码，设备序列号作为用户名。供应流程预置相应盐值和验证器；手机从扫码结果取得该次证明材料。云端只保存添加标识摘要，不通过普通查询接口返回原值。不得只用广播名称或MAC选择、认证设备。

一次性添加标识本身不能最终绑定：还必须验证登录账号的家庭权限、本次配网窗口内的真实设备证明，以及该设备认证后的云端确认。认领任务和主动配网窗口各限180秒；过期重试生成新任务和新随机挑战。初次配网证明在绑定完成后失效，不能用于再次进入配网或转移设备。密钥、私有添加材料、设备二维码产物和固件产物均不入Git。

已经绑定其他家庭时拒绝认领，不显示该家庭的成员或历史。设备本地重置或清除Wi-Fi不自动解除云端家庭归属。重新配网、解绑和转让后续单独实现；当前维护仍沿用已授权的设备操作方式。

## 5. 蓝牙配网与自有服务连接

蓝牙配网使用加密且验证持有证明的官方协议，SSID、密码和本次添加任务只在该通道传给设备；云端不接收或保存家庭Wi-Fi密码。

技术基线优先验证乐鑫`network_provisioning`的BLE传输与Security 2。现有BluFi已转维护模式，源码分支不能直接作为产品兼容保证。正式适配前必须完成微信客户端与选定、锁定版本组件的握手/加密/分包互通验证，核实ESP-IDF 6.1下两种S3固件的内存与构建情况；不自行设计加密协议，也不为绕过不兼容退回明文或无认证模式。兼容验证失败先修正技术设计，不发布不可用的配网入口。

产品固件的默认启动入口固定为自有HTTPS地址，校验证书；语音入口使用自有WSS地址。启动响应不能把它切到小智官方云，不提供面向家庭用户的服务器URL输入框。当前HTTP/WS测试入口不能直接视为产品扫码注册入口。

设备通过独立凭据向自有服务认证，将经蓝牙收到的本次任务与随机挑战提交给服务端。服务端据可信设备身份确定device_id；不接受手机提交的MAC、family_id或device_id作为设备认证结果。启动配置的下发也必须验证设备身份，不能沿用“共享私有URL＋MAC即可领取凭据”作为新注册方案。

## 6. 管理后端最小改动

沿用现有Go管理服务，不增加独立注册微服务。新增能力分为：

1. **可信供应工具**：受控云端命令准备设备身份与一次性添加信息；不覆盖现有设备身份、凭据或绑定。消费者无需接触此步骤。
2. **家庭认领接口**：登录后验证指定家庭的设备添加权限，创建有时限的待确认任务；查询和取消仅限任务创建者及其仍有效的家庭权限。
3. **设备确认接口**：独立设备认证，验证任务与挑战，原子地消耗添加信息并创建绑定；拒绝重放、过期、错误设备、跨家庭和并发抢占。
4. **持久授权读取**：设备激活状态、稳定身份和家庭绑定必须具有明确的权威来源，管理查询和语音准入看到同一次提交后的状态。当前启动时静态加载方式需要适配，不能要求每增加一台设备就手改JSON或重启语音。

绑定提交须同时确定设备、家庭、绑定版本、服务端实际起点和添加操作者的明确授权；其余成员不自动获得正文权限。现有管理账号模型还没有家庭管理员字段，最小新增家庭成员的`CanAddDevices`权限，默认false；由受控配置显式授予，不能把“是家庭成员”视为可添加设备。设备列表可见与正文阅读继续使用现有独立授权，添加操作者只获得本次绑定后新记录的明确权限。

建议接口契约如下；均为新增设计，当前服务尚未提供这些接口：

| 接口 | 输入与认证 | 返回与约束 |
| --- | --- | --- |
| `POST /api/family/onboarding` | 已登录家庭账号；一次性添加标识、family_id、可选昵称 | 校验添加权限后返回随机任务ID、随机确认挑战、expires_at及设备序列号/型号；重试不延长旧任务 |
| `GET /api/family/onboarding/<id>` | 同一登录账号及仍有效的家庭权限 | 返回waiting/confirmed/expired/cancelled；confirmed才含稳定device_id和绑定起点，无密码或设备凭据 |
| `DELETE /api/family/onboarding/<id>` | 同上 | 取消未提交任务；若确认已经提交则返回confirmed结果，不能将已绑定伪装成已取消 |
| `POST /api/device/activation` | 独立设备认证凭据；任务ID、随机确认挑战 | 服务端依据认证设备核对任务，原子确认或返回已确认的相同结果；不从请求正文接受设备身份或家庭归属 |

手机经已认证的加密BLE会话向设备传递Wi-Fi配置及任务ID/挑战；设备拿到网络后调用activation。设备侧不接收来自手机的服务端URL或长期云端凭据。

提交失败不得留下已消耗二维码但无绑定的半完成状态；并发认领只有一个家庭获胜。待确认任务不授予正文权限。绑定后的聊天与记忆仍按真实归属和起点读取，旧数据不导入、不回填起点。

公网接入通过HTTPS域名和明确的路由范围提供小程序所需的家庭登录/添加接口；内部后台、私有供货工具、原始记录与Mac登记/配对接口不一起公开。保留回环管理入口与独立语音服务边界，补齐公网登录限流、TLS下的会话处理及反向代理可信来源检查。

## 7. 实施顺序与可验证交付

1. **协议与接口准备**：确认AppID/HTTPS域名；定义一次性认领与设备确认契约；云端完成选定蓝牙安全协议的已知向量互通及两种S3候选构建。此阶段不改正式语音或刷现用设备。
2. **云端认领闭环**：实现可信供应、待确认任务、设备认证确认、原子绑定及运行时授权更新；云端自动验证正常、过期、重放、越权、并发、断电重启恢复及写入失败。兼容已有设备的稳定ID与原绑定边界。
3. **小程序和固件适配**：实现上述简单向导、选定协议客户端与S3配网入口、自有HTTPS/WSS默认地址；演示模式与真实连接结果明确区分。Wi-Fi密码不进日志或持久化客户端存储。
4. **隔离部署与现场验证**：先在云端隔离环境发布，用户方便时完成Android/iOS手机及微雪/M5的真实扫码、错误密码恢复、蓝牙断开、云端不可达、并发认领、绑定后页面可见与旧记录隔离。对话内容/播放验收仍是独立事项。

所有依赖安装、运行时测试、构建和服务部署在云端执行；Mac用于代码/Git与后续客户端。先取得隔离验证结果，再安排正式服务迁移与实体设备更新。不能用合成设备确认或构建通过替代现场配网成功。
