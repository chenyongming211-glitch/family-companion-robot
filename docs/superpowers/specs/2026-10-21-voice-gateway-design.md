# 最小实时语音网关

用户已确认：自研 Go 主干，按需参考开源实现；M5StopWatch 使用小智固件，经小智 WebSocket 协议接入千问原生实时语音。当前只实现对话和打断，不增加家庭业务。

## 边界与数据流

- 自研协议处理与会话状态；Gorilla WebSocket 处理连接，系统 libopus 处理编解码，不复制第三方服务端业务代码。
- 小智 v1/v2/v3 二进制封装；设备上传单声道 Opus，解码到 16 kHz PCM；千问返回 24 kHz PCM，按 60 ms 编码并实时节奏下发。
- `hello`、`listen`（manual/auto/realtime）、`abort`、`tts`、`stt`；提供健康检查和带独立引导密钥的 OTA 配置地址，不推送固件升级。
- WebSocket 使用设备 token 鉴权；默认最多一个活动设备；密钥只读取环境变量，日志不记录音频、转录、token 或上游原始错误。
- 一个会话调度循环拥有状态和下行写操作；输入通道、回复 PCM 队列、历史文本均有上限。下行按 60 ms 发送，避免把整段回复提前压入设备。

## 打断与上下文

- 设备 abort 或千问 speech_started 中断当前回复；立即停止旧音频下发，清空 PCM 队列和编码器状态，发送 tts.stop。
- 每个上游连接使用代号；重建连接后忽略旧连接事件。回复 ID 再隔离同连接的迟到音频。
- 千问文档未提供可靠的已播放音频截断接口；中断时重建上游会话，将有界的近期用户转录与已下发完成的回复作为历史背景注入系统提示词，明确中断回复未完整播放。正在说话时保留并重放有限输入音频，避免重连丢掉插话开头。
- 设备没有播放确认事件，不能声称精确知道用户听到了哪些字。首次版本以不保留被中断回复全文为保守策略，实际设备清缓存和 AEC 仍需硬件测试。
- 设备断线结束上游会话，重连建立新的临时会话；跨设备连接的长期记忆不在本阶段。

## 验证

- 协议封装、实际 Opus 编解码、PCM 分帧与残帧、旧事件抑制、打断清队列、手动提交与自动 VAD、鉴权与资源释放。
- 使用本地假上游的真实 WebSocket 集成测试，覆盖先回复、打断、迟到旧音频、新回复。
- Linux 部署后用模拟小智设备发送真实 Opus，验证千问回声链路和第二轮对话，再做中途 abort 验证；保存去密钥的测试结果。
- 最后由真实 M5StopWatch 验证扬声器回声、播放中收音与实际停播延迟。

## 部署

使用现有 Ubuntu 服务器和 family-robot 账户，API Key 沿用 root 管理的 /etc/family-robot/server.env。systemd 运行网关，独立 releases 目录和 current 链接支持回滚。初期 HTTP/WS 为设备联调入口，使用独立随机引导 URL 和设备 token；正式使用前再配 TLS 域名，不将该入口描述为生产就绪。
