# 业务聊天分段与归档读模型

## 目标与实施边界

用户批准下一批落实已确认的30分钟规则：明确结束优先、30分钟内重连续同一聊天、超时新建、跨零点不拆分，页面保留轮次、状态和原连接/播放证据。现场发言暂缓。本批基于已经持久保存的服务端事实提供真正的服务器分段/逻辑归档；两端复用同一Go规则。原始记录即持久事实，稳定ID从首轮来源计算，重启无需另建数据库或复制正文。

不同时改语音生成、模型上下文、设备协议或固件，不新增摘要模型/后台执行框架。当前明确结束来源为既有listen.stop→client_stop；abort是插话，client_closed/transport_lost不是明确结束。不新增自然语言结束意图识别，也不把归档分类当作故事内容修复或实机通过。

## 最小结构

1. `internal/conversation`纯Go生命周期归约器：只接规范化来源与事件以及显式now，无文件/HTTP/正文/账号/时钟副作用。
2. `internal/management`从已有安全源读取生成时间事实，复用原project输出播放证据，调用归约器；新增/chats，旧/conversations保持连接来源兼容，记忆来源链接不改变。
3. Vue真实聊天列表使用/chats，按聊天开始日期分组、显示轮数/连接数/归档状态和详情来源。原连接详情仍可打开；mock不改变。

正文权限先于事件读取。业务分段需检查有效user_text，因此/chats列表也要求正文许可；无此许可的用户可继续使用原连接元数据接口，但不能读取正文派生分段。设备/家庭/绑定ID与版本组成独立作用域，不能串家庭、设备或绑定区间。仍只纳入本次绑定后获授权来源，不导入历史。

## 生命周期规则

- 只有非空有效最终user_text才创建/续接聊天。心跳、轮询、唤醒、预览、无效输入、自动提示不创建聊天/续时。
- 接受一轮后为待结算，生成/播放期间无论多久都不自动归档。
- 有效I2S终态playback(played/drained)结算；generated仅在明确sent=0时可作为无音频结算；interrupt/generated_interrupted明确sent=0也可结算。有音频的interrupt、turn_error缺失sent不代表播完，要等终态、drain_timeout或源关闭；后二者为未知结算，不能升级播放证明。播放终态可先于generated持久记录。
- 一轮首次可靠/未知终态冻结其生命周期结算时间，重复或迟到的同轮事实不续时、不创建聊天、不复活归档。结算可能先于user_text入日志，先保存该事实并在接受时关联，idle时间不早于接受时间。
- 所有已接受轮次结算后，从最后有效输入/首次结算的最大时间开始计30分钟；边界恰好30分钟归档，结束时间为锚点+30分钟而非页面查询时刻。归档后接受新输入生成新聊天。
- source closed仅将其未结算轮次标为未知结算；client_stop额外立即归档该来源最近所在聊天，已归档不重开。无有效输入的新来源client_stop可结束同作用域仍活动且不早于其连接开始的聊天；老来源不能终止后来新建的聊天。
- 不完整尾行不消费；在最后完整事件时间插入不确定标记，阻止把该来源最近的聊天轻率超时归档。已明确结束/此前已超时的聊天不复活。没有有效输入的部分源只报告pendingSources，不造空聊天。
- 没有终态又没有关闭的崩溃遗留源无法证明死亡，保留待结算，不根据mtime、管理重启或另一个连接猜测结束。

归档为可从持久事实和版本1规则重新得到的逻辑状态，不另存正文副本。ID=`chat_`+完整SHA256，输入为无歧义编码的策略版本、家庭/设备/绑定ID及版本、首轮源sessionID/turnID。对相同完整源集合，重复读取/进程重启ID和分段相同；不承诺任意回填、更改/删掉首轮历史后ID完全不变。本批不支持历史导入/删除，且无正文缓存，删除源不会被索引副本复活。

## 时间、读取与界限

按全部获准来源读取后再分组/分页。每源时间必须有限、正数、非递减且不早于源开始；采用完整行at，跨源按at、来源开始、sessionID、行次序稳定排序。源关闭优先完整closed事件，缺失才用EndedAt；已关闭manifest与closed原因冲突则失败。显式now在读取完成后取值，未来事件不能伪造活动时间。

复用原目录/manifest复核、普通文件、无符号链接、重复JSON字段和播放计数检查。每文件32MiB/行2MiB/每源2000轮保持，另限制每请求64MiB原始事件、100000事件、10000轮，总量超限明确503，不返回截断后假装完整的聊天。完整坏行/时间错误失败503；尾部待写则pending。来源必须有body授权后才开events。

## API与页面

- GET `/api/{admin|family}/chats?device=&offset=&limit=`：device可省略表示全部获正文许可设备；显式空/错误/无正文设备失败。列表通用标题、时间、轮数/连接数和状态，无转写/摘要/生成稿。响应items/hasMore/pendingSources。
- GET `/api/{scope}/chats/<chat_64hex>?device=`：按来源重新授权后返回详情；审计成功才输出正文。列表同样做无正文list_chats审计。旧/conversations及记忆接口不变。
- ConversationDTO兼容扩展startedAt/lastActivityAt/endedAt/archiveReason/turnCount/connectionCount/sources。sourceKind=business_chat，status中文进行中/待结算/已归档，recordStatus标pending尾部；sources只在详情输出。turn ID用sessionID:turnID保持跨连接唯一，附原sourceRecordID/sourceTurnID，播放内容完全沿用project。
- 列表当前页按开始日期分组，跨零点聊天仍在开始日；详情显示连接数/轮数、结束依据、可展开原连接链接。不加入网页“结束”按钮，避免只改页面状态而未停止实际语音。无数据、错误/无权和低频刷新保持。

## 验证

云端纯状态机、源适配/权限/HTTP合成回归；覆盖30分钟前/等于/后、午夜、长生成/播放、played先于generated、0音频与排空、重复/迟到、断线vs明确结束、空连接、部分尾行、崩溃未结算、双家庭/绑定、预算、重启ID一致。Mac浏览器验证两端列表/详情/来源/分页/失败隐藏、mock与手机布局。独立部署管理服务，现有语音PID/健康/保护摘要保持；实机新聊天分段验收待用户方便时再做。
