# C3 播放中语音插话

用户已授权补齐 C3 播放期上行与回声处理，复用现有服务端打断流程。按键仍负责进入/结束会话；进入后开口插话，无需再次按键。

## 数据路径

物理 ES8311 保持 24kHz MONO16、6×240 DMA。TX 回调先复制已经播放的旧 PCM，再执行 PlaybackProgress 的完成记账和描述符补充；RX 回调在同一物理时基配对麦克风与播放参考。复用已有 DuplexReference 的代次、缺块、过期和容量检查，音频处理、分配及日志均在任务内执行。

MR 两声道共同有状态重采样到16kHz，由 ESP-SR 的 C3 独立 AEC 处理，结果进入原 LiteAudioEngine 的 Opus 上行。保持本地打开的上行代次跨越 tts.start/stop。服务端仍由 Qwen speech_started 触发原 interrupt/drain 流程，按实际 DMA 回报保存已播内容。不得修改服务端 VAD 策略来掩盖设备回声。

## 先验证实际可行性

锁定 ESP-SR2.4.7 的 C3 API 与最新 master 不同：aec_create(16000,2,1,AEC_MODE_SR_LOW_COST)，512样本/32ms。版本对应官方提交 ae2b0bb5c0ded603e45ac17e902411c37cb32636；C3 processor库 blob46c4afeeac072cce6143885f9e2029e9970e5479。已查到真实 esp_aec3_dlfft 实现，而非空桩；包含软件浮点运算，不能由头文件存在推定160MHz单核上的实时性。

先用同一IDF6.1/组件锁构建专用探针，在真实 C3 上测每32ms块的处理耗时、内部堆占用及释放、输入输出非静音校验。探针不联网、不打开codec、不保存声音、不登记设备、不读写NVS、不确认OTA镜像；只输出合成信号的统计数据后重启，回退现有有效镜像。若独立AEC已超过32ms，则不能把它接入同时承担Wi-Fi/Opus的产品固件；保留稳定固件并根据真实结果选择轻量实现或硬件音频前端。

## 交付门槛

1. 原生依赖锁无漂移，目标链接确实引用 C3 AEC 库；内存/CPU有余量。
2. host 故障测试证明先取旧TX参考、RX配对、边界/代次、溢出关闭与实际DMA回报。
3. Lite引擎处理连续16k MR，不丢不足512样本的跨块尾部；异常关闭上行，不能直接送裸麦克风冒充AEC。
4. 精确构建、旧variant回归和独立审查通过，再安装候选。保留稳定app1、完整备份及所有身份/网络/记忆配置。
5. 真实扬声器播放时无自声触发、开口打断后新问题能完整回答、后续继续对话。合成/构建通过不冒充真人声学验收。
