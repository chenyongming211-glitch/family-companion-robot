# StopWatch 直接开口插话：最小固件实验

最新进展（2026-10-22 晚）：实验固件已刷入，普通对话和控制正常。首轮录像失败后补齐服务器控制事件记录，并修复了[取消先到时丢句首](../../verification/2026-10-22-cancellation-prefix.md)的独立网关缺陷。新网关已部署，用户在音量80下确认两次播放中直接插话分别停播并回答二、五；仍未完成十轮、静听累计两分钟及实际扬声器停声时延验收，详见[现场记录](../../verification/2026-10-22-software-aec-field-results.md)。以下方案与验收门槛保持不变。

当前软件交付记录见 [构建与下载验证](../../verification/2026-10-22-software-aec-build.md)。

## 已确认目标

用户明确要求：机器人播放回复时，直接开口说新内容即可打断，不需要再次喊唤醒词。待机时原有的唤醒方式保留；本次只解决活动对话中的自然插话。

本次范围是现有 StopWatch、现有 Go 网关和千问原生实时语音。不增加家庭业务、长期记忆、摄像头或新音频硬件，不重写完整设备系统。

## 已知事实与尚待实验的部分

- [M5Stack 官方资料](https://docs.m5stack.com/en/core/StopWatch)说明 StopWatch 使用 ESP32-S3R8、16MB Flash、8MB PSRAM、ES8311、MEMS 麦克风和扬声器。
- 对应小智 v2.5.2 的 [ES8311 驱动](https://github.com/78/xiaozhi-esp32/blob/v2.5.2/main/audio/codecs/es8311_audio_codec.cc)创建同一 I2S 外设上的 TX/RX 通道，声明 duplex，但输入只有一个麦克风通道，`input_reference_ = false`。这是有同时收放音基础的源码证据，不等于实机全双工已经通过。
- [application.cc](https://github.com/78/xiaozhi-esp32/blob/v2.5.2/main/application.cc) 在没有 AEC 时默认选择 auto，进入 Speaking 后关闭普通语音处理。当前设备实际发送 auto 模式，历史启动证据为 1 microphone / 0 playback reference。
- [AFE 实现](https://github.com/78/xiaozhi-esp32/blob/v2.5.2/main/audio/engines/afe_audio_engine.cc)从 codec 输入定义构造麦克风及播放参考格式，并依参考配置决定是否初始化 AEC。仅打开配置开关不足以补齐缺失的参考数据。
- [AudioOutputTask](https://github.com/78/xiaozhi-esp32/blob/v2.5.2/main/audio/audio_service.cc)可以取得最终交给 codec 的 PCM。用它生成软件播放参考具有实验依据，但该函数调用的时刻不等于扬声器实际发声时刻；DMA、codec、声学路径和重采样的时序必须测量。
- 官方源码是对应版本参考，尚未证明现有设备二进制与其逐字节一致。构建前需核对板型、分区和模型资源，保留完整依赖锁定记录。

## 方案选择

| 方案 | 优点 | 当前代价与判断 |
| --- | --- | --- |
| 设备端软件播放参考 + ESP-SR AEC | 利用现有硬件；麦克风和播放数据都在设备端，减少网络时序因素 | 需要定制固件、对齐参考并验证回声抑制；本次推荐先实验 |
| Go 服务端增加 AEC | 将算法放到服务器 | 同样要先让固件播放时上传收音，还需解决上下行时延与播放位置估计；本次不同时开发 |
| 增加硬件回采或更换音频板 | 可取得更接近实际播放的参考 | 涉及接线或结构选择；现有硬件实验有证据失败后再评估 |

## 推荐的数据流与改动

### 1. 保留板级真实输入，补充软件参考

基于小智 v2.5.2 的 StopWatch 支持制作独立实验构建。保持 codec 的物理单通道输入定义，不把它伪装成已有硬件参考。

在最终 PCM 进入音频输出的路径上复制参考数据，涵盖所有经该路径播放的声音。按实际 I2S 提交及采样进度记录，测量并补偿与麦克风的固定偏移；不能用千问原始输出或网关发送时间代替实际播放参考。麦克风及参考经有状态重采样统一到 16kHz，组成交错的 `MR` 输入送入 AFE。

参考队列固定上限为一秒 16kHz/16bit 单声道数据（32KB），记录缺帧、积压和时序偏差。播放确实静默时提供零参考；播放中参考缺失或对齐失败时，停止本次实时插话实验并回到原 auto 路径，不能带着无效参考继续宣称 AEC 可用。停播时保留已提交输出的参考尾音，随后再归零。

### 2. 先证实消回声，再启用实时上传

使用当前锁定版本 ESP-SR 的全双工 AEC。官方 [AFE 输入格式](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/audio_front_end/README.html)定义 `M` 为麦克风、`R` 为播放参考；[AEC 文档](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/acoustic_echo_cancellation/README.html)说明支持全双工处理。实际 API 以构建锁定的 ESP-SR 头文件为准，不直接照搬 latest 文档接口。

实验先验证同时收放音、参考对齐和双讲时的处理效果，再开启 realtime 模式，在播放时持续上传 AEC 后的麦克风音频。不能通过播放期间静音麦克风或丢弃用户语音来获得“没有回声”的假结果。

第一版沿用千问的语音开始检测：用户语音上传后，千问报告 `speech_started`，Go 网关停止旧回复、清空旧队列、重建上游并重放有界的近期输入。先不增加另一套本地 VAD 触发 abort 的决策，避免同一次插话在设备和云端重复取消，以及丢弃插话开头。

### 3. 明确清除设备端旧播放

在网关真正打断回复时，为现有 `tts.stop` 增加可选的 `reason: "interrupted"`；正常播完的 stop 不带该标记。旧固件仍可忽略这个可选字段。

实验固件收到带打断标记的 stop 时，清理本地解码、待播放队列及过期解码任务，保持麦克风处理和上行；普通 stop 保持正常收尾。已进入 I2S/DAC 的短尾音单独测量，不能把清队列当成物理扬声器已经静音。参考数据也必须覆盖这段实际尾音。

原有网关对迟到回复、连接代号、输入重放及中断上下文的处理保留。继续使用原有音量、屏幕 MCP 工具；两分钟空闲退出策略保留。

## 实施顺序与止损条件

1. 固定上游源码提交、工具链和组件版本，记录许可证及补丁来源；先原样构建 StopWatch 基线。v2.5.2 的组件清单要求 ESP-IDF >=6.0.1，并固定 ESP-SR 2.4.7；选定可复现的工具链后保存完整锁定结果。
2. 先为参考采样顺序、重采样计数、队列上限、停播尾音和重置边界编写行为测试，再实现参考路径。为可选打断标记和设备清队列分别加回归。
3. 构建实验固件，检查分区及镜像大小，生成镜像和回退资料；构建成功不算声学通过。
4. 在用户知悉的测试窗口刷入可回退实验固件，验证启动、网络、原有工具、播放和收音，再测 AEC。全双工或参考对齐失败则停止该轮测试，不继续叠加语音识别参数调整。
5. AEC 可用后接入现有网关和真实千问，进行直接开口插话及连续多轮测试。若参考稳定但消回声或双讲不合格，保留测量证据，回退并报告该硬件方案尚不可用，再讨论硬件回采或服务端方案。

现有设备完整 Flash/NVS 备份为私有材料；实施前校验文件、分区、板型和恢复步骤。先保留现有配置与可启动固件，禁止通过整片擦除解决配置问题。刷机将短暂中断手表使用，实施时提前告知；不静默打开串口导致手表复位。

## 可验收结果

首轮使用桌面、安静房间、距离约 0.5 米、音量 80 的条件，记录实际条件；记录测试前设置并在结束后恢复。通过后再测音量 100 及其他距离，不预先承诺远场性能。

- 机器人单独播放累计两分钟，不能因自身回声产生用户转写或误打断。
- 在回复不同位置直接说完整的新句子，至少十轮，至少九轮识别新意图并转入新回答。以开口到旧回复实际停止为端到端时延，首轮目标至少九轮不超过一秒；同时记录中位数、最差值及失败样例。该数字是待验证目标，不是当前能力。
- 插话开头不能被重连或清队列丢弃；用“停一下，先告诉我……”等带明确开头的短句检查。
- 新一轮没有旧音频迟到混入；模型不把尚未播完的旧回复当作用户已听完。
- 连续十轮后设备稳定，无重启、音频任务卡死或队列持续增长；音量、亮度和两分钟待机功能继续可用。

端到端停播时延用现场同一段录音/录像辨认开口起点和旧回复终点；设备及网关时间戳用于分段定位，不能代替实际扬声器停止的证据。

实验只在明确的测试窗口采集必要的麦克风/参考/AEC 对照，保存于私有目录；正常运行不记录音频或对话转录，日志不包含 Wi-Fi、token 或 API Key。记录中分开报告：原样构建、软件回归、AEC 声学结果、真实千问链路和现场插话结果。
