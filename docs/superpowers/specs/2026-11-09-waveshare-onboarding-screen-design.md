# 微雪屏幕扫码配网

用户已确认开发设备屏幕上的设备码、配网进度和绑定结果。目标是首次添加时无需另找标签；保留既有小程序、Security2和服务端confirmed规则。

## 最小方案

采用云端生成的微信小程序码，供应时作为私有位图放入同一设备的工厂NVS。设备离线即可显示；不在设备保存AppSecret，不用普通QR替代微信小程序码。对比临时从云端下载（首次尚未联网）及普通文本QR（无法从微信直接进入本小程序），供应位图能复用已有平台码工具且适合当前流程。

微雪屏幕采用浅色背景、蓝紫标题、完整白底设备码与清晰中文反馈。待扫码显示“微信扫码添加设备 / 请在小程序中完成登录和配网”；收到Wi-Fi凭据显示连接中，获得IP后显示校时/云端确认，只有设备独立认证确认或合法恢复已绑定状态后显示成功。错误Wi-Fi、校时失败、超时、缺失/损坏设备码有明确反馈。成功后短暂展示并恢复既有机器人显示；码在配网过程结束后隐藏，普通已绑定启动不显示一次性码。不添加动画、导航或新服务。

## 私有码供应与格式

工具新增screen输出格式，直接处理本次固定官方接口返回的同一图片，固定请求280×280、黑色码线、白色不透明背景。云端Pillow解码，拒绝非280×280、多帧或损坏图片，转换为逐行MSB优先1bit（1黑0白），不做缩放。输出FRC1：magic4字节、宽高各LE16、36字节device_id、载荷CRC32 LE32、9800字节位图，总9848字节。摘要只用于发现损坏，不授予身份。文件同工厂包0600/私有父目录0700，失败不留下部分文件，不打印凭据；默认原图输出保持兼容。

NVS工具只接受微雪的可选screen_code，校验格式、CRC与工厂包device_id一致，仍不写入原始认领字符串。固件读取同一NVS，验证长度/尺寸/CRC/device_id；配网显示不依赖联网。不将私有图像、NVS、固件、凭据放入Git或下载到Mac。

## 实现边界

复用现有Display锁及LVGL，微雪专用显示owner渲染持久配网页面；其他板型和普通固件保留。状态上报串行、过期工作不能覆盖终态；UI不能决定认证/绑定成功，Wi-Fi成功不是添加成功。180秒窗口、证书/校时/设备证明与取消清理保持。

直接main开发/提交/推送。所有依赖、测试和构建在云端。先用合成码和身份执行真实NVS/位图/状态/显示验证，再构建两款S3，避免共用候选编译退化。Mac仅源码/Git与测试客户端。既有微雪迁移、真实AppSecret平台调用、刷写和手机BLE依赖实际私有材料与目标设备确认，不能把候选通过记作已刷或真机成功。
