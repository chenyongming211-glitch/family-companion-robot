# Xmini C3 按键语音接入

状态：用户已选择“先稳定接入：按键开始对话，暂不要求播放中语音插话”。本文件落实已说明的专用固件、可信播放回报和独立设备身份方案，按此范围实施。

## 目标与硬件

将已连接的 Xmini C3 接入现有 Go 18041 → 千问 Realtime 产品入口。USB/ROM 确认为 ESP32-C3 revision 0.4、16MB Flash；现有小智 2.2.6 的启动日志确认 SKU=xmini-c3、SSD1306、ES8311，原始 USB 芯片标识与运行时自定义网络 MAC 不同。登记身份必须以设备实际发送的 Device-Id 为准。

复用锁定小智 v2.5.2 / IDF 6.1 的 `main/boards/xmini/c3` 硬件定义，新增独立产品 variant，不替换原 variant。只在 main 开发、提交、推送。运行依赖、测试及目标编译在云端或 GitHub Actions；Mac 负责源码/Git、USB 与后续实体测试。

## 首版行为

- 开机联网后待命，按键开启连续问答；按键结束连接，断开后可再次开启。
- 首版不启用本地唤醒词、不运行 S3 的 AFE/MultiNet/软件 AEC，不声明播放中语音插话能力。播放期间停止向云端发送麦克风音频，实际播放排空后恢复聆听。
- 上行开关跟随当前连接与实际播放状态；封口/网络下发结束不等于喇叭已经播完。关门时拒绝迟到编码帧，开门时不能补发播放期积压录音。不使用固定秒数静音来冒充播放完成。
- OLED 保留配网、待命、聆听、播放、错误等原有状态；不迁移彩色光球。音量控制仅在设备 MCP 实际提供相应能力后启用。
- Go 继续负责模型、搜索、当前设备工具、文字记录与近期记忆。不同设备身份及记忆隔离，不恢复三段式、不启用暂停的声纹/多人/提醒/判题功能。
- C3产品variant固定选WebSocket，不使用NVS里保留的旧MQTT账户。编译默认OTA URL为空，首次启动前通过USB置入产品bootstrap与该C3独立WebSocket资料；不在引导失败时选择旧平台协议。

## 播放适配

现有 Go 设备入口强制协商 `playback_progress_v1` 和 `playback_drain_v1`。原 ES8311 驱动没有这一实现，不能只改地址或虚假声明支持。

新增 C3 专用 ES8311 派生驱动，复用 `PlaybackProgress` 状态机，以真实 TX DMA 完成回调累计 24k PCM 已播样本。回调独占 DMA 填充，不与普通 codec writer 竞争。保持有界队列、连接/回复/硬件代次、封口与完成顺序；队列不足、格式错误、错误回调节奏、内存或注册失败均使回报无效，不伪报完成。无 AEC 参考缓存和 S3 专用任务。

硬件开关和 codec open/close 由 task mutex 串行化；ISR 只做有界拷贝和受临界区保护的状态变更，不执行阻塞等待、分配、日志或 task mutex。核对实际 IDF 配置、mono16/24k、DMA 长度、BCLK 与 ES8311 的驱动生命周期。故障时不降级成无回报的产品连接。旧 M5/Waveshare 路径保持其配置和行为。

## 构建、凭据与安装

C3 使用独立且审计过的 native dependency lock 与 SHA256，不将 S3 的 target 锁误称为 C3 锁。关键 ESP-SR/codec/IDF 版本保持已有固定版本；若目标条件造成依赖集合不同，记录确切差异。最终产物核验源码提交、patch/overlay、SDK、有效配置、依赖字节、镜像、分区和包内摘要。

刷前重新确认唯一 USB 目标，读取安全状态，完整备份本机 16MB Flash 并校验长度/摘要；私有备份、凭据和生成镜像不进 Git、不上传含秘密的 Flash 到云端。解析原分区与 OTA 选择后制定最小写入范围，不整刷其他板型的 merged 包。上游 Xmini 板级代码包含 VDD_SPI_AS_GPIO eFuse 操作：先只读核对，产品 variant 不新增或自动执行 eFuse 烧写。

完整备份已确认原 2.2.6 布局：NVS `0x9000+0x4000`、otadata `0xd000+0x2000`、PHY `0xf000+0x1000`、两个 `0x2f0000` 应用槽在 `0x20000/0x310000`、2MiB assets 在 `0x600000`。产品采用独立 `partitions/xmini-c3-family-16m.csv` 保留这些地址和大小，上部8MiB不分配或清空。新 app/assets 超出原槽即拒绝，不自动迁移分区；目标构建后再确认能否安装。

云端为 C3 新增独立 MAC/token 绑定，保留原设备凭据和身份库；bootstrap 只发该设备的连接资料，不把模型 Key 送到设备或 Mac。Wi-Fi 和引导配置通过 USB 写入所需键，保留其他 NVS 内容；若缺少用户指定网络信息，先完成其余可验证工作再询问。云端配置有启动快照时，在空闲窗口加载并保留回退，不为接第三种板型无条件扩大并发；当前 max_sessions=2，三台同时对话单独评估。

## 验证与完成标准

1. 云端先失败后通过的真实生产驱动 host harness：实际 DMA 完成才计数、回调顺序/尺寸/节奏、队列满、迟到代次、重连、封口、排空、idle 重开、故障及内存/回调注册失败；ASan/UBSan 与正常优化构建均执行。
2. 输入门控验证：播放期不发音频、迟到编码帧不越界、全部完成前不恢复、排空后新语句可发、断开后不误恢复。现有共享音频/协议回归和四个旧 variant 不退化。
3. C3 精确目标编译和最终产物核验通过后才安装；应用及所有改动区回读一致，未授权改动区与刷前一致。确认原硬件初始化、按键、OLED、云端独立鉴权与正确归属。
4. 分开记录模拟云端证据与真人实机证据。实体测试覆盖多轮问答、回答完整播放、结束/重开、跨会话记忆、音量、断网恢复和待机；未取得真人反馈不补记听感通过。不把这次接入称为现有 Mac/微雪回声或长讲解问题的修复。
