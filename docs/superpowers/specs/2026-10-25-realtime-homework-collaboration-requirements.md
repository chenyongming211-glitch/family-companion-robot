# Realtime 统一语音入口与多模型判题协作：需求说明

日期：2026-10-25。状态：**需求整理，尚未开始本功能的开发或部署**。

本文件从 [Realtime、后台任务与专用模型总体设计](/Users/chen/code/家庭陪伴/docs/superpowers/specs/2026-10-24-realtime-task-specialist-design.md) 中收敛“统一语音交流＋后台调用其他模型判题＋同一音色讲解”这一项功能，用于后续单独评审和安排开发。它是总体方案中的子项，不额外计作一套语音架构，也不取代其他已记录需求。

## 1. 一句话需求

用户始终通过 Realtime 与助手自然交流；需要判题时，Realtime 通过工具调用向后台提出请求，由后台选择并调用 DeepSeek 等专用模型分析真实题目材料，保存结果，再交给 Realtime 以当前对话的同一音色讲解和回答追问。

## 2. 用户要获得的体验

- 从提出判题请求到听讲解、继续追问，都像在和同一个助手交流，无需手动切模型或重新开始对话。
- 判题在后台进行，等待时仍能说话、插问其他事情或取消检查。
- 助手始终知道当前检查哪道题，追问不串题，补拍或改答案后使用新的材料。
- 图片或题意不清时，由助手结合实际情况自然确认，不猜题、不强判。
- 只有后台实际拿到结果，助手才说明判题结论；失败、尚未完成和无法确定均如实表达。

## 3. 角色分工

| 角色 | 负责内容 | 关键边界 |
|---|---|---|
| Realtime | 听懂请求、提出业务工具需求、自然说明状态、讲解结果和回应追问 | 不以口头承诺替代后台执行；不自行编造照片、结果或成功状态 |
| Go 后台 | 获取和关联材料、校验请求、选择分析服务、执行后台任务、保存与交付结果 | 拥有真实照片、题目、任务及结果状态，决定何时和向哪个终端交付 |
| 专用分析模型 | 识别题目与学生作答、判断对错、分析步骤、给出解释依据 | 返回业务分析内容，不直接向用户发声，不单独控制设备或对话 |
| 用户终端 | 语音采集/播放、上传实际图片；具备相机时执行拍照 | 依据实际能力工作，不假定现有手表已经具备拍照闭环 |

DeepSeek 是目前优先考虑的判题服务，具体 API 型号、权限和效果在后续验证。后台应能替换分析模型；用户仍使用相同的“检查作业”能力。

“同一音色”指沿用本次 Realtime 对话当前配置的声音，不将专用分析模型的独立声音交给用户，也不要求切换到三段式的另一种音色。

## 4. 标准交互流程

1. 用户说：“帮我看看这道题做得对不对。”
2. Realtime 理解请求，通过工具调用申请检查作业。
3. 后台确定目标题与可用图片：没有图片时等待拍照/上传；图片有多题且目标不清时，由 Realtime 澄清。
4. 后台将真实照片、学生作答、必要口述补充和检查要求交给配置的专用模型。
5. 分析期间，Realtime 继续接收和处理用户发言；必要时自然说明正在处理，不要求用户保持沉默。
6. 后台获得分析结果，校验内容与题目关联并保存，向当前对话提供有效结果。
7. Realtime 在合适的话轮，用相同音色解释判定、错误原因或所需补充信息。
8. 用户继续问“这一步为什么这样算”，系统沿用同一道题、同一照片和有效分析结果。

## 5. 功能要求

### R01：统一语音交流入口

普通聊天和判题交互均由 Realtime 面向用户。判题模型在后台提供分析，不要求把整段对话切换到另一套 ASR→文本模型→TTS。

本功能不要求每次请求始终使用同一条上游网络连接；重连后仍应找回必要业务状态，维持同一助手的交互体验。

### R02：通过工具提出真实业务请求

Realtime 提出“检查这道题”等能力需求；后台负责参数、材料和状态校验，以及选择具体供应商。

助手只有在后台实际接纳请求后，才能说明已开始相应处理。缺图片时应说明需要图片，不能声称已经在看照片。模型说“检查完了”本身不能把任务标成完成。

### R03：真实图片、题目与作答关联

后台保存照片、目标题、学生答案及任务之间的关联，保证后续提问能找回正确材料。

首个版本支持单张图片、一道目标题。图片可以来自明确的测试上传入口或支持拍照的终端；小程序和相机硬件的完整开发不作为本功能首次联调的前提。

照片包含多题时，先确定目标；模糊、缺页、遮挡或关键数字不清时，要求补拍或确认必要文字。没有拍到解题过程时，不编造学生在哪一步算错。

### R04：判题内容

分析结果应能表达：

- 识别出的题干、学生答案，以及实际可见的解题步骤。
- 正确、错误、部分正确或信息不足的判断。
- 有依据的错误位置和原因；必要时给出正确答案或解法。
- 适合后续讲解的提示、关键计算事实和需要确认的内容。

后台检查结果完整性、关联和明显矛盾。格式正确不代表判题准确，实际效果仍需使用真实作业样本验收。

### R05：同一声音讲解，保留分析结论

Realtime 根据有效结果调整语气、解释长度和表达方式，但不能随意改动题干、学生答案、关键数字和判定结论。

默认采用易懂、分步、可追问的讲解方式；根据用户问题决定提示或展开，不用固定长话术代替交流。

“分析模型判得对”和“Realtime 讲得对”分别验收。同一音色不等于已经保证口述事实准确。

### R06：等待分析时仍能聊天

判题是独立后台任务，不阻塞实时音频和新的对话。用户可以在等待时问“二加三是多少”，助手正常回答，原判题按状态继续。

可有简短、自然且真实的进度说明；不要求每次判题都先播固定确认句，也不能把确认句当作判题答案已返回。

### R07：插话、取消和换题分开处理

- 普通插话：按当前语音播放策略让出话轮，不自动取消已经接纳的判题。
- 明确取消：“这道题不看了”，停止该任务后续执行或结果主动交付；无法立即停止远端计算时，也不能继续播报其迟到答案。
- 明确换题：更新当前目标题，旧结果不得覆盖新题或突然抢读。
- 只停止讲解：保留已完成分析，用户之后可以重新查询或要求继续解释。

结果完成时若用户正在说话或助手正在回答新问题，先保存结果，再等待合适时机。默认向发起端交付，不向其他在线终端广播。

### R08：同题连续追问与修改后的再检查

“为什么这里要进位”“第二步再说一遍”等追问沿用同题已有结果，依据足够时不重复判题。

“换一种方法”“我把答案改成这个了”等涉及新计算、新答案或新材料的请求，按需要再次调用专用模型，并保留新的分析版本。补拍后旧结果不能覆盖新材料对应的结果。

“这一步”“上一题”等指代能由当前记录确定时直接理解；无法唯一确定且会影响回答时，由 Realtime 自然澄清。用户不需要记住内部任务编号。

### R09：必要业务记录与恢复

至少保存本次功能所需的照片、题目、学生答案、检查要求、分析结果、结果版本、任务状态和相关追问关联。

区分“分析结果已保存”“已开始讲解”“讲解完整播放或交付未知”。网络已发送、模型生成了完整文字，不代表用户已经听完。

重连或服务重启后能查询已保存结果；不能因为重连而重复分析、重复收费或自动重读全部答案。确切播放位置未知时，不编造逐字续播点。

本项只要求判题所需的业务记录与恢复，不同时建设面向全部聊天的通用档案查询或个性记忆系统。

### R10：失败与不确定性

缺材料、模型不可用、超时、非法结果或无法确定时，保留真实状态，由 Realtime 自然说明或提出必要问题，普通交流尽可能继续。

无法确认外部请求是否已执行时，不自动重复提交相同付费分析。用户明确重试时保留尝试关联；不能以静默重试掩盖未知结果。

专用模型失败不自动把用户切到另一套语音链路，也不让助手自行编造判题答案填补失败。

## 6. 本次范围与其他方案的关系

本项包含：Realtime 工具交互、单图单题判题、必要后台任务与存储、同音色讲解、同题追问、取消/换题和错误恢复。

本项不包含：

- 两套完整语音后端的统一入口或自动切换；现有三段式继续保留。
- 全量聊天档案、通用跨会话记忆、真实定时提醒。
- 微信小程序全套界面、摄像头硬件/固件的完整适配。
- “小满”产品身份配置、多人识别、声纹登记和按人归属；已有暂停决定不变。
- 整本作业批改、自动拆分全部题目、多模型投票或无限自主规划。
- 通用故事/长内容的精确原稿断点恢复；该需求仍保留在总体方案中。

后续其他终端可以复用同一判题后台；用户无需为不同终端分别维护两套题目和结果业务。

## 7. 首个版本的验收场景

| 场景 | 预期行为 |
|---|---|
| 用户发起判题，但没有图片 | 请求上传/拍照，不假装已经看到 |
| 清晰单题，学生答案错误 | 正确关联材料，指出有依据的问题，并用原音色讲解 |
| 学生答案正确 | 给出正确判定，不为制造讲解而编造错误 |
| 关键数字或字迹不清 | 自然请求确认或补拍，不强行定对错 |
| 判题等待时插问数学问题 | 能回答插问，原分析不因普通插话丢失 |
| 结果就绪时用户正在说话 | 保存结果，等待话轮，不抢话 |
| 追问同一道题某一步 | 找回原题与有效结果，依据够用时不重复分析 |
| 修改答案或补拍后再检查 | 产生新分析版本，旧结果不覆盖新答案 |
| 换题后旧结果迟到 | 不串题、不突然播报旧答案 |
| 明确取消后远端仍返回 | 不复活任务，不自动讲解 |
| 重复工具请求、断线和重连 | 不重复创建同一检查请求；已保存结果可查 |
| 专用模型失败或结果未知 | 如实说明，不编答案或盲目重复付费提交 |
| Realtime 接收了正确分析结果 | 最终语音的关键数字、对错与结果保持一致 |

验收使用真实作业样本，分别检查识题、作答识别、判定、解释依据、最终口述和等待时的交流体验。模型调用、后端测试与服务运行均在云端；Mac 仅用于代码/Git和测试终端。本文没有执行上述验收。

本次只记录这项需求，不安装依赖、不新增模型调用、不改运行程序和服务。后续技术设计可参考原总体方案，但数据库表、工具参数、模型配置和接口细节不作为本需求说明中的既成实现。

进入开发前需要确认首批题型和真实样本、首个图片入口及专用模型的实测选择；这些不影响当前需求整理完成。供应商凭据只在云端配置，不写入文档或客户端。
