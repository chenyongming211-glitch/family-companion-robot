# 插话后自动接续原任务：设计提案

日期：2026-10-23。状态：待用户评审。本轮交付设计，未修改业务代码、固件或生产配置。

**2026-10-24更新：用户已选择服务器端LiveKit链式架构，后续以[新架构细化](2026-10-24-server-livekit-design.md)为准。** 本文保留历史方案，其中“普通问答保留千问原生、不迁移框架”的选择不再是默认路线；固定原稿、真实播放检查点和接续验收要求仍沿用。

## 1. 目标与交互

验收目标是：唤醒一次，机器人讲故事或数数时可以直接插话；先回答插入的问题；用户说“继续”，自动回到原任务中断处，无需用户报起点。空闲超时回到待机，重新唤醒不会自行执行旧任务。

- 故事：完整播完第3句，第4句中途打断，回答旁支问题后，“继续”从第4句开头重讲，然后按原故事往下讲。允许重读未完成句，不跳过尚未播放的内容，不临时换一个故事。
- 数数：确认播完8，9尚未完整播完，则“继续”从9开始，保留原终点50；已完整播完9，则从10开始。
- 连续插话：恢复过程中再次打断，使用最新播放进度，不能退回第一次中断位置。
- 普通路径不询问用户起点；异常或语义确实不明确时才进入故障说明/澄清。

当前“起点未知时询问”是保护措施，不是自动接续的完成标准。文字记录与跨会话恢复已上线；本提案补齐其尚未完成的自动接续部分。

## 2. 当前事实与原路线的困难

核对基线：main 040ce07，业务源码5772dfb。当前有设备I2S播放采样回报、原任务/revision、输入归属、生成前ACK以及文字快照。

- `internal/gateway/playback.go` 从待播PCM缓冲取60ms一帧，成功下发后增加sent；这个计数不是已播位置。
- `session.go` 打断时清理pending、取消原生生成；`playback_progress.go` 保存任务与设备采样。当前没有正文单位到音频的可信对应表。
- 原生生成稿可能远早于声音到齐，现有事件没有提供可直接使用的逐字音频区间。标点或事件到达顺序不能产生实际播放断点。
- 83次离线推理发现正文领先、早停、静音幻觉和数字识别差异；构造音频片段坐标不能冒充自然语流的词尾真值。

现有证据见[记录与恢复结果](../../verification/2026-10-23-record-recovery-results.md)、[离线对照](../../verification/2026-10-23-record-recovery-alignment.md)和[原生事件核对](../../verification/2026-10-23-playback-text-capability.md)。本轮没有重跑这些实验。

## 3. 路径比较与推荐

| 路径 | 优点 | 主要代价/缺口 | 判断 |
|---|---|---|---|
| 固定内容、按单位合成、按设备回报提交进度 | 每句/数字从一开始就有明确的文字与音频归属，不需要事后猜最后一个字；可恢复原稿 | 长内容新增TTS输出路径；需验证音色、首句延迟、段间停顿、设备坐标和调用成本 | **推荐先验证** |
| 保留完全自由的原生长语音，增加输出ASR/对齐 | 保留原生长语音的表现力，长期可用于一般自由回复 | 仍需处理早停、识别错误、边界幻觉、资源开销和播放坐标；现有实验未通过 | 保留研究候选，不作为首版唯一依赖 |
| 缓存原生未播音频，按游标重播 | 同一次生成的声音可保持一致 | 打断时尚未生成的尾部不存在；重启后无音频；不能单独解决完整任务和模型上下文同步 | 可作以后优化，不能单独满足本需求 |

推荐方案有明确的局部链路变化：**故事/数数采用固定内容＋分段TTS，普通实时问答、收音和插话继续使用现有千问原生实时语音。** 不迁移LiveKit/Pipecat，不把现有全部问答替换为ASR→LLM→TTS。

这是设计建议，不是已验证可用的生产方案。若要求故事本身也必须保持当前原生语音输出，需选第二条路线并继续边界实验，不能把本提案的分段保证套用过去。

## 4. 内容先固定，播放进度独立管理

网关维护一份有版本的任务稿和一个完成游标。故事全文是任务数据，不直接作为“已经说过”的助手历史注入原生对话。

| 内容 | 含义 |
|---|---|
| task_id / content_version | 原任务及其固定稿身份；改写内容产生新版本，旧回调不能推进新版本 |
| original_request / target | 原请求与终点；数到50不能因为插话变成从50数到100 |
| units[] | 有稳定编号和正文的播放单位；故事按短句/自然分句，数数按单个数字 |
| completed_through | 已获得有效设备证据的连续完整单位前缀，初始0 |
| playback_epoch / playback_id / unit_ranges | 本次播放身份和各单位在音频中的位置；重播分配新身份 |
| status / revision | preparing、playing、paused、completed、discarded、replaced、cleared及其单调版本 |

故事首版先取得一篇有明确结尾、通过长度限制的完整文字稿，再开始播放，不在恢复时重新自由生成后半篇。生成失败或超过限制时明确失败/请求缩小范围，不能截断后声称故事完整。

任务入口必须绑定当前真实用户转写和输入代次，在放行语音前确定是故事/数数内容任务还是普通问答；进入内容路径时不能同时放行原生模型自由生成故事音频。复用现有归属分类和ACK机制，但需要新增首次内容任务的入口，不能假设现有“已有暂停任务时”的分类器已经覆盖这一场景。

数数在确认起点、终点和步长后由网关构建有界序列；每个数对应一个单位，终点由任务数据控制。首轮验收1～50。不可凭大模型一句“继续”重新决定范围。

普通完整句优先保持整句；长句按自然分句切成更短单位。首版建议单任务最多4096字符、128单位，单单位最多64字符；这些是拟定资源上限，不是已实测最佳值。合法长句不能靠硬截断丢字，拆分后连接应保留原文。

## 5. 语音合成与播放归属

优先验证百炼Qwen-TTS Realtime的手动commit路径：一段文本对应一次合成，只允许一个在途合成，按response身份归属返回PCM；完成当前合成后可预取下一单位。候选为`qwen3-tts-flash-realtime`，是否对现有业务空间/密钥/地域开放尚未实测。

官方接口支持手动提交文字、24kHz PCM输出和响应完成事件。使用`commit`模式控制单位边界，不能用自动切分模式假设文字边界。[客户端事件](https://help.aliyun.com/zh/model-studio/qwen-tts-realtime-client-events)、[交互流程](https://help.aliyun.com/zh/model-studio/interactive-process-of-qwen-tts-realtime-synthesis)、[服务端事件](https://help.aliyun.com/zh/model-studio/qwen-tts-realtime-server-events)。

音色是否能与当前原生语音一致、同一密钥是否可用、持续多次commit的实际行为都须先测，不能因同属千问而推断兼容。官方两页对commit事件的说明存在表述差异，实际采用哪组触发/响应事件以隔离探针结果固定，不能盲目拼接两段示例。

- 每个单位在完整合成成功、PCM合法后才成为可播放的已知音频单元。不能仅凭audio.done判断成功；检查终态、响应身份、非空/偶数字节PCM和错误事件。
- 当前单位加一个预取单位保留在有界内存。建议每单位最多15秒、最多720000字节PCM，合计不超过1.44MB新增音频数据；超限失败，不默默丢音频。另核算现有pending及复制峰值。
- TTS成功终态与非空PCM也不能证明逐字发音无误。P0须人工核验专门生成的输出是否按稿读完，并覆盖静音/截尾/数字等反例；这不采集用户声音，也不把同一模型生成的正文当作独立听辨真值。
- 一个内容播放块可包含多个单位，网关记录每单位的起止采样；单位交界不发送tts stop，避免固件每讲一句就切回聆听/触发自动listen.start。
- 末帧补零、编码器前视延迟、设备解码/重采样、DMA尾部都纳入标定。必要时在块末增加经过验证的排空尾部；补零不能算作文字。
- 主内容与旁支语音共用现有下行/AEC路径，但输出归属互斥；不能同时混音，旁支音频不能推进故事游标。
- 文字生成、TTS预取、磁盘保存均异步；收音、立即停播不等待它们。打断后关闭/退休当前TTS代次，迟到PCM不再进入扬声器。

分段播放可能降低长语音的韵律连贯性，并增加文字生成/语音合成调用。只在内容任务路径调用TTS，避免同一段故事先生成一份原生语音再生成一份TTS。记录实际usage和耗时后比较成本，不预设免费或更便宜。

## 6. 完成证据：先验证坐标，再提交游标

核心规则：**合成完成、收到音频、下发成功都不推进completed_through；只有匹配的有效设备播放前缀覆盖该单位末尾，才提交其完成。**

1. 同一任务版本/播放代次下记录单位PCM区间；通过实测确定其与设备24kHz I2S采样前缀的对应及安全余量。
2. 有效、单调的设备progress可提交完整单位，interrupted final结算本次最后位置；延用已有250ms有限等待，不延迟即时停播。迟到final仅能更新仍匹配的旧播放结算，不能覆盖已经恢复的新播放。
3. 中断落在单位内部，则该单位未完成。故事重播该句，数数重播该数字，随后继续余下内容。
4. “通常重读当前未完成一句”只适用于回报健康且坐标已验证的路径。回报丢失时可能退回更早的已确认点；不能承诺所有异常下最多重读一句。
5. 无效、越界、倒退、旧身份或超时回报不推进；不按语速/墙钟猜。遇到无法证明的坐标，保留最后可信检查点，必要时说明需从较早点重读，不能静默跳过或伪造精确断点。

现有固件先作为待验证对象使用。用相同codec版本和生成的测试音频验证编码/解码边界、末帧排空、DMA归属及中断清队列。需固件探针时仅输出身份与计数，不上传用户麦克风音频；只有证明协议/计数确实缺信息时才提出最小固件补丁。不能把此前模拟I2S回报当成这一步已经通过。

这条路线将“自由语音中识别最后一个字”变成“已知短音频单位是否完整交付”，仍需设备标定，但首版不依赖新的辅助ASR。

## 7. 插话、恢复与上下文

1. 检测到真实插话，立即停主内容播放，保存已确认游标与待结算播放身份，保留原稿。原生语音处理新问题。
2. 一问一答或多轮旁支不覆盖任务稿、原终点或游标；旁支本身不创建另一份可恢复长任务。首版只维护一个暂停主任务。
3. 用户说“继续讲/接着数”，复用现有输入归属分类。网关根据游标决定恢复单位，并绑定原任务版本，不让模型自由猜起点。
4. 恢复新建播放代次；需要重新合成的单位使用保存的原稿。用户指定起点/从头重来仍可覆盖游标，但来源单独标成用户选择。
5. 给主模型的ACK快照只描述已确认播过的内容、当前未完成单位和任务状态。未播全文仅作隔离任务稿，不混入普通“助手已说内容”；必要时重建原生上下文，不能只追加提示词而保留超前正文。
6. 后续插话按最新代次更新游标。最后单位完整播放且终态保存成功，任务进入completed；普通“继续”不得续出51、换故事或把完成任务重新激活。
7. 放弃、改成新故事、清空、设备重连沿用现有权威状态和归属校验；清空同时取消TTS/文字生成、清除任务稿与游标，迟到事件不能复活旧任务。

可以回答“刚才讲到哪了”，依据最后确认完整单位。不能把正在播的半句或已经生成但未播的下一段说成用户已听过。

## 8. 保存与恢复

复用现有异步快照存储，新增固定稿、单位编号、完成游标和内容版本；仍按设备隔离，默认7天、可手动清空，不增加数据库服务，不持久化音频。单位稿与身份计入快照容量，越界明确失败。

任务稿在首播前需完成一次持久化确认；后续完成游标异步提交。保存错误不能声称已跨重启记住，播放/停播不等待磁盘；内存中的已确认进度仍可用于当前连接恢复。

重连/进程重启时只恢复已成功保存的连续单位前缀。丢失最后一次写入最多造成保守重读，不能跳过未确认内容；重新合成剩余文字即可，不恢复旧音频坐标。重新唤醒不自动开讲，等“继续”。旧版快照没有单位稿时保持原有未知保护，不伪造新游标。

## 9. 实施顺序与每阶段出口

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| P0：隔离可行性探针 | 现有Key/地域调用候选TTS；固定故事8～12句、1～50逐单位合成，测试单连接连续commit、错误/取消、音色和usage | 响应归属明确，无正文串段；合成内容完整；音色、首句延迟和段间停顿达到可接受水平，否则调整候选并重审取舍 |
| P1：设备播放标定 | 同codec路径短脉冲/可辨单位/末帧测试；核对DMA前缀与单位结束；覆盖静音、断流、队列积压、中断 | 有可复现坐标关系与保守余量；断在边界前不能把后单位判完成；无法证明则禁止启用 |
| P2：任务稿与游标 | 分段、固定原稿、版本、完成前缀、快照兼容及复用ACK/路由 | 单测/故障注入证明旁支不覆盖、旧代迟到不生效、终点正确、写失败不谎报、清空不复活 |
| P3：真实模型与模拟设备 | 故事/数数多次插话、继续、再插话、待机重唤醒和隔离进程重启 | 不依赖用户报起点，保留原稿/终点，按确认单位继续；明确模拟与实机证据不同 |
| P4：现场验收后启用 | 同一手表、音量80，多轮故事/数字；同时检查AEC、误停、连贯性 | 下列现场标准通过，才给该设备启用自动接续；保留可回退开关 |

P0～P3的大部分工作可先自行做；P1中真实硬件计数采集与P4听感/插话需要可连接手表及现场配合。测试期间不录用户麦克风；如需人工标注，用专门生成的机器人输出，不默认开启现场录音。

## 10. 验收标准

以下是拟定的启用门槛，不是已经达到的测试结果。

- **故事10轮**：60～90秒固定稿，覆盖句首、句中、句尾和连续两次插话。正常回报时从首个未完成句恢复；不漏句、不换稿、不反复问起点，原故事最终讲完。
- **数数10轮**：1～50，覆盖数字内部/数字间隙及同一轮恢复后再插话。以人工听辨的最后完整数字与设备证据共同核对，恢复时不漏数字，不越过50；未完整数字允许重读。
- **边界与故障**：直接构造每个单位边界前后截断，覆盖乱序/迟到final、有效回报缺失、断流、清空、放弃、替换、保存失败和重启。没有证据的单位不得被标成完成。
- **性能与听感**：记录首句延迟、段间额外停顿、插话停播延迟、说完“继续”到恢复出声时间和实际费用。首轮目标：预取成功时额外段间停顿p95≤250ms，已缓存恢复出声≤1.5秒（从“继续”的完整转写确认起）；与当前原生链路做同条件对照。目标未达到须报告差距，不隐藏进固定提示音。
- **发布条件**：代码审查、Mac/Linux检查和隔离真实接口通过，加上P1/P4实机证据。模拟回报、生成正文正确或一次听感成功均不能单独宣告完成。

第一轮不承诺故事逐字精确到中断音节。用户需求以“不漏内容、原任务连续、通常只重读当前未完句、无需报起点”为准；逐字无重读可作为之后独立优化。

## 11. 本次范围

只解决一个暂停主任务在旁支问答后的自动接续及其可信播放检查点。不增加长期人格、家庭成员记忆、向量库、摄像头、工具平台或框架迁移。此次推荐方案尚待确认；不能把本设计文件提交或现有测试通过描述成自动接续已经上线。
