# 插话后按播放进度接续：候选设计

2026-10-22补充：用户已确认先对照千问官方与 LiveKit、验证并复用，再决定辅助 ASR。该前置阶段已完成[源码与实测记录](../../verification/2026-10-22-upstream-realtime-contracts.md)，首批 Go 生命周期规则已实现并隔离测试，尚未部署。它不等于本文件中的设备播放回报和完整接续机制已实施；辅助 ASR 仍未选为必需依赖。同连接、create/delete ACK 均不能独立证明已播上下文正确，后续必须补足实际播放边界与原任务状态。

## 问题与目标

当前网关可以停止旧回复、回答插话问题；但继续时可能只讲片段，或从原目标五十开始继续五十一。上游生成速度比播放快，生成稿尾部不是用户听到的位置；当前设备又没有播放进度回报。仅保存生成稿和改提示词已经现场失败。

目标是保留原任务目标与暂停位置，使用户明确要求继续后，从附近完整语句恢复，继续遵守原范围。允许重讲暂停处的短语以避免截断字词；不宣称逐字或逐采样无缝接续。数数、故事及朗读使用同一机制，不增加专用数字计数器。

用户补充的 Codex 体验是本方案的行为参照：打断后保留已说部分，回答新问题，明确要求继续时接回原任务。界面出现文字记录并不能证明内部依赖额外 ASR，也不能证明约一秒等待用于上下文写入。公开的 [OpenAI Realtime 文档](https://developers.openai.com/api/docs/guides/realtime-conversations#interruption-and-truncation)说明按已播放时长截断音频上下文的机制；WebSocket 由客户端报告边界，WebRTC/SIP 由服务端管理输出缓冲。文档同时说明该动作不提供精确截断后的文字稿，所以保存可见文字不是唯一实现方式。这里引用的是公开 API 原理，尚未核验 Codex 通话的具体实现。

因此先明确“原任务 + 已播内容 + 中断状态 + 插话问答”的连续上下文契约，再选择同步手段。原方案将辅助 ASR 提前写成必选，现修正为千问缺少可验证原生同步能力时的补偿候选；不得由 OpenAI 的事件推定千问同样支持，也不得把界面文字当作播放进度证据。以下辅助 ASR 数据流仅适用于选择该补偿路径后的实现。

## 路径比较

| 路径 | 依据与代价 | 判断 |
| --- | --- | --- |
| 上游原生按播放边界同步音频上下文 | 不必再次识别自己生成的语音；仍需已播边界与协议支持 | 若当前千问接口能验证成功则优先；现有探针尚未确认，不能直接使用 |
| 设备播放进度 + 已播音频片段转写 | 定制固件增加进度回报，网关增加一次有界的辅助 ASR；需要处理迟到、失败和接续时序 | 原生能力缺失时的推荐补偿候选，尚非已批准的必选依赖 |
| 仅用网关已发送片段转写 | 改动较小，但已发送不等于设备已播放，设备积压或停播时会高估位置 | 只用于隔离原型，不作为可靠现场交付 |
| 保留未播音频后直接续播 | 已完整生成时可以避免重新生成内容；上游在生成途中自动取消时，缓存并不包含全部余文，仍需处理后续生成与上下文 | 可后续优化，不单独当作本次通用修复 |

官方事件未提供可直接使用的逐词时间戳；当前实际接口的 truncate 探针没有确认。辅助 Qwen-ASR 已通过同空间合成音频调用，单次约0.5秒；完整证据、样本局限和生成稿异常见[调查记录](../../verification/2026-10-22-resume-after-interruption.md)。

## 最小数据流

1. 每个回复有独立播放代号。设备按该代号回报单调的播放采样进度与有效状态；新回复、重连和重启隔离，迟到或越界回报不能修改别的回复。基准使用与本回复关联的实际输出完成边界；不能直接复用全局 I2S 计数、网络接收计数或提交计数，不能将现有通知播放器的进度回调误当作 DMA 完成证据。
2. 网关保留当前回复最后12秒下行 PCM，约576KB，不含麦克风。收到播放中插话，先发送现有打断 stop、清除旧待播；保存一份暂停记录，包含原用户请求、回复代号、播放边界及已播片段。最多保留一个原任务暂停记录；旁支问答及其再次被打断不覆盖原目标。明确切换新任务才替换，目标不明确时确认，不能按最后一条助手回复盲目覆盖。
3. 在有效播放边界前提取最多8秒尾部音频，使用同业务空间 `qwen3-asr-flash` 辅助识别。只处理机器人自己的已播输出，不处理现场收音。请求有超时，失败不重试循环；不阻塞立即停播，也不阻塞插话收音。音频与识别文本只在有界内存存在，正常日志不记录内容。
4. 新问题仍走当前千问原生实时语音。用户明确说继续时，模型通过网关的本地上下文工具读取暂停记录；成功结果提供原目标和已播片段，不能使用生成稿尾部代替播放进度。这里沿用现有 Function Calling 桥接方式，不将识别结果当新用户指令。
5. 播放回报缺失、无效，或识别未就绪/超时，就返回位置未知，简短确认继续点；不得猜测数字或声称已接上。用户改变原目标、放弃旧任务、会话结束或两分钟空闲退出时释放暂停材料。仅收到旁支答案完成不表示原任务完成。

## 边界与实施门槛

- 先完成设备进度与网关保留片段的对应回归，再接辅助 ASR；不能把“服务器发送过”标成“设备播放过”。重复/乱序/越界进度、DMA 尾音、停播清队列与旧代次必须有行为测试。
- 异步识别结果必须按会话与暂停代号核对，迟到结果不能覆盖新暂停。语音 stop 的及时性、插话句首重放、音量/屏幕控制保持现有已验证行为。
- 既有120秒待播上限保持；新增音频尾部上限12秒、单个暂停记录、单个识别请求，设备重启或连接关闭立即失效。产品日志仅记录状态与耗时，不写文字或 PCM。记录不持久化、不提交 Git。
- 先隔离测试数到不同终点、故事、朗读及旁支问答后继续；再测 ASR 超时/权限失败、旧结果迟到、多次打断与目标变更。不能用字符串包含终点代替实际完整输出检查。
- 原生输出可能有内容错误，进度同步不能保证模型逐字计算正确。生成稿和实际数字音频均须验收；出现越过终点、漏数等仍算失败，不把能播放或正常 stop 当内容正确。
- 固件构建、Go 测试、发布身份、现场接续结果分别报告。刷机前提前告知，保留当前固件回退；不在用户播放中因采样到期关闭实时模式。
