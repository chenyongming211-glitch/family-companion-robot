# 时钟UTC与北京时间一致性修复

2026-11-14用户在音频恢复开发期间报告：屏幕原为北京时间，随后再次少8小时。本项作为原任务中的独立缺陷修复，一并验证同一固件体积，不改变时钟布局。

## 已核对机制

工厂配网启动SNTP（UTC系统时间），OTA校时却把服务器`timezone_offset=480`直接加进Unix时间戳后写入系统时钟。桌面`FormatDesktopClock`假定系统时间已是本地墙钟，使用gmtime。SNTP后续刷新覆盖OTA的偏移值时，桌面自然少8小时。该冲突由当前实际固件来源确认，需用真实校时块重现覆盖顺序。

## 最小修复

- 系统时间统一保持标准UTC，OTA不再把时区偏移加进Unix时间戳；SNTP与OTA写入语义相同。
- 当前产品默认北京时间（POSIX `CST-8`/等价UTC+8），在应用启动早于校时/显示处设置一次；OTA收到合法时区分钟偏移时更新展示时区，不修改时间戳。
- 桌面使用localtime_r按所配置时区显示，避免缺加或重复加8小时。其他使用localtime的原系统页面同时一致。
- 使用现有libc，无依赖/新服务/字库/布局变化。参数应拒绝非有限或越界偏移；无效偏移不改变已有时区。
- 共用准备补丁，基础与工厂源码都包含同一行为。服务器接口/密钥/设置不变。

## 验证

- 先测试真实OTA校时块：UTC毫秒输入不被加偏移；随后模拟SNTP给同一UTC时刻，桌面仍为北京时间。
- 覆盖跨日/日期星期、重复校时、缺失或非法时区和合法分钟偏移，未校时仍`--:--`。
- 既有纯布局测试显式固定其测试时区，避免依赖云服务器本地TZ；另有真实时间语义用例证明北京时间。
- 云端相关测试、最终支持机型全套及同一原生固件体积检查。当前设备未因此修改，需候选安装后现场复验。
