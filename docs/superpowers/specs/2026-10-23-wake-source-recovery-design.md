# 唤醒来源与失败恢复

用户已授权按顺序修复：网关唤醒来源归属、固件发送失败恢复，再处理播放位置与文字对应；用户不在现场，本轮不刷机。

## 网关

根因是把ASR与唤醒词文字相等当作来源证据。改用设备实际阶段：小智先发唤醒缓存，再发detect/start。首次连接仍按正常VAD配置初始化；在首个listen.start之前收到缓存PCM时，先切manual分段再照常转发，detect将此前的有界缓存单独commit。只有该次commit返回的输入身份属于wake，ASR“小智/小志/其他名字”不改变来源。commit ACK与首个start都到齐后，在manual模式创建一次问候；收到response.created后才恢复VAD并转发业务语音。manual按键模式不生成自动问候，保留用户采集和延迟stop。

等待commit期间，后续业务PCM放入有界队列；问候response.created后按顺序完整转发。8秒内未ACK、缓存异常或队列超限均关闭会话，不能静默丢字、假装唤醒成功。没有缓存的detect不能给下一条真实输入贴wake；没有detect的普通listen/manual路径仍正常工作。已进入连续对话后的再次detect不把业务输入升级成wake。

唤醒输入来源随generation/itemID传入response/playback/paused记录，迟到转写只更新文字，不能改变来源。旧连接事件不得占新任务。纯wake回复不占暂停槽，下一条包含唤醒词的真实指令仍可暂停。这里缓存是设备唤醒检测前的音频阶段，不承诺把同一缓存内的任意完整业务指令重新切分；新增测试保护的是start之后的业务语音和拼接不丢失。

不增加同音字名单，不增加辅助ASR，不过滤或替换缓存音频，不更换模型与正式提示词。VAD阈值和静音时长只在连接初始化配置，后续模式切换只发送type或null，避开已实测的音频append后不可修改参数约束。

## 固件

缓存SendAudio失败立即终止该次唤醒，清理音频连接并回到可再次唤醒状态；不再继续发送detect/start。唤醒detect及开始聆听控制也需向调用方回传成功状态，失败同样走恢复。保留正常分支与无缓存配置，避免因错误处理让唤醒检测永久关闭。

主机测试编译实际准备源码的函数/包含文件，注入首/中/尾包及控制发送失败，确认恢复、后续重试与正常路径。CI构建普通及软件AEC两款固件；产物保留，不刷入手表。

## 验收与边界

Go先跑确定性RED/GREEN、迟到/乱序/超限/超时和连续输入，再用隔离真实千问复跑问候重叠、数数插话、查询原请求。分开报告原请求修复与继续位置：后者仍未知，不用生成稿或时长比例冒充已听文字。

播放位置阶段本轮继续做无需硬件的能力验证与契约测试，已有I2S进度语义保持；需要真实逐字位置证据才能实现精确接续，不因前两项通过就宣称全链路完成。
