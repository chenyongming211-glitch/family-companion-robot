# C3 PCM 云端隔离评估

用户已在阅读复验记录中的方案后选择“继续做隔离评估”。本阶段交付可重复的协议/状态机测试与资源预算，不部署正式服务，不刷写设备；C3 保持稳定按键版本。

评估采用当前 main 的云端源码副本，加评估目录内的显式原型补丁；仓库 `internal/` 产品代码保持原状。PCM 使用当前C3的version1封装、独立的 `pcm_s16le` 格式及 `pcm_s16le_v1` 能力，单声道16k上行/24k下行、60ms帧。帧必须分别恰为1920/2880字节，不自动把错误PCM解释成Opus。现有Opus协商及其他客户端路径由完整回归保护。

原型在共用 Session 内只适配传输和对应ASR输入：PCM绕过编解码，输出按1440样本补齐最后一帧，省去仅Opus需要的312样本补尾。取消、样本窗口、鉴权、设备归属、记忆和控制策略保持原代码；通过实际测试验证沿用的是同一取消/drain及DMA回报校验。输入未开启listen时仍丢弃业务音频并保留有界唤醒预算。

与新增独立转码代理相比，原生PCM适配可避免在云端增加一次有损转码和额外连接；与保持Opus相比，需要新增格式协商和终端PCM队列预算。本阶段选择原生适配原型，只在云端副本生效，不增加正式监听端口。

测试先在未打补丁副本运行并确认因格式不支持而失败，再应用补丁验证：协商和错误帧、PCM逐字节保持、唤醒音隔离、播放期上行、7200样本窗口、真实回报排空与迟到包隔离、输出ASR、任意完整/尾帧的时钟。使用httptest回环、假供应商和内存合成数据，无真实模型调用、凭据或录音。

资源评估使用已取得的C3片上探针原始统计，明确其CPU下限和codec工作区范围，检查实际产品队列。协议通过只允许进入“有资格准备资源探针/固件设计”，不证明FD算法声学有效、网络稳定或产品内存足够。下一次固件前必须设计固定字节预算的PCM队列及无录音的mic/ref/out能量、削顶、参考配对和耗时统计；不能沿用压缩帧队列数量后默认内存不变。
