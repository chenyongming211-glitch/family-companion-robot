# 当前微雪迁移到扫码配网

用户已选择使用当前微雪，先备份再迁移，保留现有记录。USB 被动枚举的 MAC `44:bd:8d:79:1f:e8` 与云端设备 `dev_ce26243f0d2f0b8019bfe45796307b48` 一致；进入 ROM 后仍须独立核对。

## 范围与约束

- 直接在 main 开发、提交和推送，不建分支或 worktree。
- 只迁移当前微雪 ESP32-S3；不改变其他设备、语音算法或模型。
- 保留原 device_id、设备资料、family-home 原绑定及其 2026-11-09 10:05:08 北京时间起点、账号和正文权限。历史文件不搬迁、不删除，不重新开放绑定前记录。
- 云端执行依赖、运行测试、构建、备份、发码和服务部署。Mac 只操作代码/Git、微信客户端以及连接 USB 的内存字节转发；设备备份、密钥、NVS、固件不得落 Mac/Git。用户后续明确要求远程展示码，仅设备码PNG可临时显示于Mac私有目录/Codex，不公开发布或入Git；FRC1及其他私有产物仍仅云端。
- 不写 eFuse；首次刷写前须确认芯片/MAC/容量/安全配置，双份完整 Flash 备份一致且备份可读。
- 刷写使用已验证的 c22b807 微雪完整工厂候选，私有 NVS 最后覆盖；先完整读回验证，再正常启动。

## 迁移方式

沿用现有设备 ID，在工厂设备记录上增加可选 migration_binding_id，指向原绑定。可信 CLI 在云端核对旧 MAC/令牌摘要与 voiceidentity 设备记录，并核对管理平台原设备/有效绑定后，生成新的工厂私有包。只追加一项工厂认证记录，不编辑旧身份文件，也不在准备阶段撤销旧固件认证。

首次扫码仍走现有小程序、一次性认领、安全 BLE 和独立设备确认。迁移认领只允许原绑定家庭中已具备该设备访问权且有添加权限的账号。确认后复用原设备和原绑定，不创建第二台设备、第二条绑定或扩大正文授权；确认回执记录原绑定起点。其他家庭、失效绑定、重复供应、旧身份不匹配和无权限账号均拒绝。普通新设备供应/认领行为保持。

原绑定作为历史归属继续存在，新的工厂认证在独立云端确认前不准入语音。准备完成后，才从旧认证注册表移除目标微雪一项并重启原语音二进制加载新注册表；M5 主身份及其他条目保持。新固件通过工厂认证返回相同 device_id，历史聊天和记忆仍沿原路径读取。

## 备份、安装和回退

云端私有目录保存旧完整 Flash 两份及摘要、原认证注册表、管理配置、身份文件和受保护文件摘要。USB 通道仅监听本机回环并经 SSH 隧道转发。先读芯片与安全状态，再两次读取 16 MiB 并逐字节比较。

生成与同一私有包匹配的官方设备码、SRP/NVS，并核对手机可打开对应小程序版本。以 16 MiB 擦除态镜像覆盖候选各段和私有 NVS，校验每段后写入；完整读回与预期镜像一致才启动。启动只观察配网状态，不主动开麦或触发模型。

失败时停止新路径，恢复已验证旧 Flash 和目标旧认证项，重启原语音二进制。管理配置回退只移除本次新增工厂/认领数据，并发改变须保留，不盲目覆盖整份旧配置。保留原绑定和源记录。

## 验收边界

迁移后端：云端行为测试、race/vet/build、独立规格和质量复审。

安装：芯片身份、安全状态、双备份、候选来源/段落、私有码与 NVS 绑定、完整读回、实际启动分别留证。

手机：用户扫码、登录、BLE 权限、输入 Wi-Fi、设备独立确认与原记录访问需要实机完成；未观察到的步骤保持待验证。发码 API 成功不等于手机能打开相应版本，编译成功不等于实刷成功。
