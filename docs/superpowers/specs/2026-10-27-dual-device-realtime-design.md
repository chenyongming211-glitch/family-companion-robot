# 双设备接入当前 Go Realtime 核心

状态：用户已批准“服务端→第二台固件→双设备验收”的顺序。当前开始服务端阶段，后续板级实现按本范围继续；不要求用户再次选择分支或执行方式。

## 目标与范围

让原M5StopWatch与Waveshare ESP32-S3 Touch AMOLED 2.16接入同一18040/18041 Go语音核心。复用已经实现的设备ID、会话ID和记录归属，以及已播上下文、取消生成/已收音频排空、身份与搜索。各设备分别鉴权、拥有独立对话与播放生命周期，断开一台不影响另一台。

原M5继续运行已保留的A/e61f079，作为设备基线。第二台需要独立固件目标，不能刷M5应用或merged包；通用代码抽取与板级差异分离，不复制两套语音业务。多人声纹/个人归属、判题提醒、长期记忆、旧Python/三段式恢复、暂停的音频故障自动恢复均不加入。

## 服务端设计

### 设备凭据与引导

新增共用的受保护设备凭据读取模块，供当前Realtime鉴权及既有8000 OTA引导复用。配置文件只在服务器，schema1，条目为规范化MAC与各自独立token；0600/私有权限、大小/数量上限、重复MAC、非法MAC/短token/无效JSON均拒绝，不把秘密写日志或会话记录。

现有`ROBOT_DEVICE_TOKEN`、`ROBOT_ALLOWED_DEVICE`继续作为单设备兼容模式。新增可选`ROBOT_DEVICE_REGISTRY`路径：配置时加载只读凭据快照，并要求原MAC/token仍在表中且一致；没有配置时沿用原逻辑。复用voiceidentity.Store.BindXiaozhi生成和保持稳定ID，新增凭据表不是重新实现设备身份库。

既有8000 OTA仅在配置凭据表时按已注册MAC下发自己的token和18041地址，继续要求原有不可猜测bootstrap路径；不增加公开自助注册，不向第二台下发第一台token，也不在此处自动下发跨板固件。旧8000语音WebSocket的准入保持原配置，不因OTA扩展将第二台接回旧语音路径。凭据生成、配置与部署在云端，provider key不进入Mac。

### 容量与生命周期

以明确的会话租约替代单个busy/active指针。命令行提供有界`max-sessions`配置：兼容默认1，当前部署设2，允许范围1..8；同设备至多一个活跃会话，重复连接拒绝而不抢掉已有连接。未知设备、错误token及跨设备token不得占用名额。

租约的设备key来自鉴权结果，不信任客户端伪造device_id；只有持有本次租约者能释放该槽。连接升级失败、正常断开、处理错误均回收自己的租约；旧清理不能释放其他/新会话。关闭服务时先拒绝新连接，再关闭全部活跃连接，有界等待各自清理。

Mac一次性票据保持120秒有效、一次使用及Origin保护。支持不同设备的多个待用票据同时存在；同一设备重新配对可替换它自己的旧票据，不能替换别人的。匿名兼容入口保持旧单设备行为并计入全局容量，票据表需清理过期项和限制数量。

健康信息保留busy表示“存在活跃会话”，以免旧空闲部署检查误判；增加active_sessions/max_sessions及capacity_full等明确字段，不泄露设备凭据。

### 状态与记录

每个Session独占模型连接、输入/输出队列、已播上下文、取消代次与文字记录目录；共享产品身份仅为不可变配置。继续由已有Ownership写入device_id/session_id，客户端不能覆盖。重连设备ID不变、session_id更新；本阶段不自动合并跨设备/跨会话记忆。

## 第二台固件边界

锁定上游已有Waveshare2.16目标配置为480×480、24k输入/输出且具有ES7210参考输入；M5为466×466，并使用现有软件参考适配。必须保留各自的屏幕、触控、ES8311/ES7210、I2C/I2S引脚、电源与省电实现，不能让Waveshare伪装为M5硬件路径。

共享小满配置、协议、实际播放进度核心与A绘图算法；图形布局按板型尺寸拟合，语音状态仍依赖真实收音/完成播放证据。新增Waveshare专用variant，M5已确认行为不变；128×128/32KiB像素缓冲、既有小表、低帧率/静态降级、待机熄屏停动画保留，功耗不能由代码推定。

第二台先完整备份16MB Flash，再规划兼容原NVS/独立身份及storage的分区。现有assets3MiB不足小满模型约5.13MiB，必须迁移模型资源空间；原M5的分区不改。具体写入范围与OTA选择、回退、逐块回读在板级计划中按目标产物落实，所有前置检查通过后才能写入。

3. 空闲时部署18040/18041及必要的OTA引导改动，保留二进制、unit、环境和原设备身份数据回退；原手表验证不退化。
4. 第二板型构建、产物/资源/分区/备份核验与安装；分别验证真实收音、回声处理、播放时钟、插话排空、断线/待机及A动效。
5. 两台实机先轮流聊天、插话与重连，再分离声学干扰验证并发。同房间同唤醒词的抢答仲裁单独设计，本阶段不能声称解决跨设备声学串音。
