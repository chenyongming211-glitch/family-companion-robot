# Realtime讲述完整性提示优化

2026-10-25，用户已批准先优化提示词、实际复测，再判断是否需要其他机制。

依据：15:30的真人会话第6轮请求讲故事，模型正常生成9.84秒音频，只介绍小狐狸阿橙的居住环境；服务端正常结束，客户端全部播完，无取消或运行错误。第7/8轮用户追问为何停止，模型两次再次询问是否继续。

本期在Go `Product.InstructionsFor`的背景JSON之后加入独立讲述指导：默认约120字的完整短故事，含事件、行动与结果，用户指定篇幅优先；长故事每次至少完成有进展和阶段性结果的一段；用户催促未完成故事或明确续讲时自然承接、直接推进，只有对象不清才反问。避免仅介绍人物/场景、仅准备语或反复征求同意。遵守用户指定篇幅、停止、换题；普通问答保持简洁，插问先回答新问题，不擅自回到旧故事。不把候选已播记录当作精确逐字位置。明确position=complete、boundary=complete_response等表示音频播放范围，不能据此判断故事/任务完成。实际人物与情节取已播记录；去掉可被照抄的示例故事，运行时没有固定播报。

只改变模型指令，不新增运行时模型调用、自动续播、完整性分类器、关键词拦截或固定语音。音频、排空、身份、搜索和近期上下文保持。Python冻结基线不改；差异测试显式剔除这一项声明的新增提示，再比较其余指令/能力/背景和状态逻辑。

云端用同一模型/音色与合成输入对照旧/新提示，检查故事是否有情节推进和结果、催促是否直接续讲、数学/停止/对象不清是否正常。人工阅读生成内容判断，长度和关键词不冒充完整性证明。随后全仓race/vet/build及一次Mac真实模型/CoreAudio插话回归。合成结果与真人听感分开说明；提示不能保证所有输出都完整。

在18040空闲时备份二进制后部署，保留现有窗口，main提交推送。用户再次开始即可使用新提示，不需重编客户端。旧服务和私有聊天正文不变，测试正文与音频不进Git。
