# 小满手表流体光球界面设计

日期：2026-10-25。

状态（2026-10-26视频反馈修正后）：用户已批准B光球/简短状态，并进一步要求灵动飘逸、省电、节省资源。04e0c7c的约9.7fps和遮字/跳动/雾蒙反馈已有记录；3ddbbb5修正已完成软件回归、独立审查、三个variant构建、仅应用安装及回读，启动Idle。当前版本的实际观感、活跃帧率、真人语音和功耗仍待验收，不把旧版测量或宿主预览当新版实测。当前实现与验收边界见[验证记录](../../verification/2026-10-26-xiaoman-watch-orb-ui.md)。下文保留已批准的设计目标，不能将建议值当实测结果。

## 1. 已确认的产品选择

- 继续使用「小满」作为唤醒词，不改变现有唤醒识别实现。
- 唤醒后以中央动态流体光球作为语音会话主界面。
- 青、蓝、紫、粉在光球内部柔和交融，外形随声音适度伸缩。
- 默认展示「正在聆听」「正在准备回复」「小满正在说话」等简短状态，不展示逐句对话字幕或聊天记录。
- 会话期间保持同一个光球，通过流动速度、形变和文字表达状态变化。
- 工程实施已另获用户授权；验收仍区分目标构建、设备回报和真人观感。

本轮不新增触摸展开聊天记录、表盘系统、麦克风开关、语音能力、模型路由、声纹、情绪识别或后台任务。预览中的按钮用于比较状态，不代表手表会增加这些按钮。

## 3. 视觉布局

会话屏幕使用近黑背景 `#020305`，以中央光球为视觉焦点。

| 区域 | 首版设计值 | 内容 |
| --- | --- | --- |
| 上方图标 | 复用现有圆屏安全区 | 电量、网络等既有系统信息 |
| 名称 | 中心约 `(233, 94)`，字号约 23px | 「小满」 |
| 光球 | 中心约 `(233, 238)`，主体直径约 220–250px | 有轻微不规则轮廓的流体球 |
| 主状态 | 中心约 `(233, 381)`，字号约 21px | 每次一条简短状态 |
| 辅助提示 | 中心约 `(233, 410)`，字号约 14px | 必要时显示「正在停播」或异常说明 |

坐标和字号是 466×466 设计画布上的初值，实施时需用现有字体与圆形遮罩复核。光球最大形变边界不超过约 280px，不能挤压名称或状态文字。

建议色板：青 `#45E8E1`、蓝 `#22A6F0`、紫 `#8851ED`、少量粉 `#ED74C1`。色彩缓慢交融，避免高亮闪烁、频繁换色或持续大幅震动。颜色只辅助表达，文字负责说明当前状态。

不把模型返回的情绪标签映射为真实用户情绪；本轮光球起伏只表达声音活动和对话阶段。

## 4. 对话状态与表现

| 状态 | 主文字 | 光球表现 | 进入依据 |
| --- | --- | --- | --- |
| 待机 | 沿用当前待机界面 | 会话光球停止刷新 | 当前会话结束或设备进入待机 |
| 唤醒/连接准备 | 「小满醒来了」或「正在连接」 | 从小光点柔和展开 | 现有唤醒、连接和就绪事件 |
| 可收音 | 「正在聆听」 | 低幅呼吸，随处理后输入音量适度伸缩 | 当前会话的实际收音门已打开 |
| 等待回复 | 「正在准备回复」 | 较小形变，内部缓慢流动 | 当前轮真实话尾/响应等待事件；没有可靠事件时仍显示聆听 |
| 正在播放 | 「小满正在说话」 | 跟随实际播放的音量包络 | 本地开始播放当前有效代次的音频 |
| 用户插话、旧尾音排空 | 「正在聆听」＋「正在停播」 | 转为聆听方向，仍保留停播提示 | 收音仍有效，且已确认取消/排空正在进行 |
| 播放完成 | 「正在聆听」 | 平滑回落到呼吸状态 | 本地确认旧播放排空，且收音门仍打开 |
| 连接异常 | 「连接异常」 | 降亮度并停止明显形变 | 当前连接断开或现有错误事件 |
| 收音不可用 | 「正在准备语音」或现有具体错误 | 低亮静态光球 | 收音门关闭、AEC 就绪等待或已有故障状态 |

「正在准备回复」是用户可见的等待状态，不代表可以读取模型内部思考、推断任务进度或预测剩余时间。不得用本地固定计时猜测服务器已经检测到话尾。

插话时的主状态取决于实际收音是否仍有效；如果收音已关闭，应显示真实准备/错误状态，而不是「正在聆听」。仅检测到音量变大，不足以断言已经成功打断。

正常连续对话在聆听、等待回复、播放之间切换，不反复退回待机。会话退出、重连和录音策略沿用已有产品行为；视觉预览不决定空闲超时、自动熄屏或常亮时长。

## 5. 声音如何驱动光球

输入与输出音量分别提供单一、归一化的包络值，UI 只读取最新快照，不持有 PCM 或音频队列。

- 聆听时：取 AFE 处理后、属于当前收音代次的输入音量，减少喇叭回声驱动光球的情况。
- 说话时：取本地实际完成播放时间线附近的音量包络，不能用收到的 Opus 包数量、整段模型生成稿或待播队列长度冒充正在发声。
- 输入输出并存时：正常播放以输出包络为主；确认插话后转向输入包络，保留排空提示。
- 包络不可用或过期时：采用低幅呼吸，不伪造连续发声，不改变音频链路。
- 不保留原始音频，不上传额外声音数据，不接入另一个模型分析动效。

建议包络变化使用约 60–100ms 上升、180–300ms 回落的平滑初值，避免每个音频帧都带来闪动。具体数值需按实机语速调整，不增加播放延迟或音频缓冲。

实施已新增当前有效收音及实际完成播放的包络观察接口。包络计算放在普通任务中，DMA/ISR回调仅发布有界标量，不做浮点遍历、分配内存或操作LVGL。

## 6. 固件职责与并发边界

建议在现有板级显示体系中划分三个小职责，不重构整个显示框架：

1. 会话视图状态：读取连接、收音门、轮次与实际播放快照，确定主状态、辅助提示和有效代次。
2. 音量包络观察：以固定成本更新输入、输出幅度及时间戳。使用有界最新值快照，旧值可以覆盖，不堆积动画事件。
3. 光球绘制：在 UI/LVGL 上下文按低优先级定时刷新。状态变化和幅度快照均不能反向控制音频。

所有 UI 对象变更继续使用现有显示锁。音频回调不能等待显示锁、屏幕传输或图片解码。重新唤醒、重连、退出会话时失效旧动画代次，迟到的旧播放/网络事件不能让新界面跳回说话状态。

首版优先复用现有本地状态与协议事件，不为动画新增独立 WebSocket、逐帧下行、模型调用或云端动效服务。如果设备缺少可靠的等待回复事件，保留聆听表现即可，不以协议改造作为界面首版前置条件。

## 7. 渲染与性能策略

2026-10-26用户补充：动效应“灵动飘逸、省电、节省资源”。该要求优先于追求更高帧率或复杂特效。修正采用轻量连续场与柔和轮廓，保持32KiB像素缓冲并减少重复刷新；实际续航/功耗必须另测，不能由内存预算、宿主速度或动画预览直接推定。

优先尝试低分辨率光球图层、预计算渐变/透明遮罩及少量形变，在 LVGL 中放大到目标显示区域。浏览器预览的 Canvas 多层渐变仅用于确认视觉方向，不直接当作 ESP32 的实现或性能证据。

工程初值与降级顺序：

- 活跃会话以约15fps为常规动效预算，优先保证轻柔连续和语音稳定；本轮不追求提高帧率，负载高时保留5fps/静态降级。真实状态变化可以立即刷新，预算不是所有绘图触发的绝对硬上限。
- 初始可评估约 128×128 的内部绘制图层；形变精度与放大方式以实机观感决定。
- 动效新增常驻内存以 PSRAM 为主，暂定目标不超过约 96KiB，额外内部 SRAM 尽量不超过 4KiB；它们是待测预算，不是已确认余量。
- 不为逐帧绘制反复分配/释放堆内存，不占用现有 AEC、I2S 或播放回报缓冲。
- 只刷新必要区域；黑色背景固定，不持续计算整屏模糊。
- 音频压力下依次降低刷新率、形变层数、纹理分辨率；必要时降为静态光球与文字。
- 待机及屏幕关闭后停止光球定时器，不以动画维持唤醒锁或改变省电策略。

相较程序绘制，预渲染短动画适合作为视觉回退，但对音量变化与轮廓的响应更有限，也有素材、存储和解码成本。首版不承诺复刻 Siri 的全部渲染细节。

## 8. 异常与既有系统页面

配网、升级、电量告警和设备启动失败等系统页面具有既有优先级，会话光球不能遮住它们。错误时必须保留可读文字，不用颜色作为唯一提示。

连接丢失后停止明显发声动效，按现有重连行为处理。重连成功也要等新会话实际具备收音能力，才能显示聆听。

既有聊天/字幕 UI 更新需要在会话视图内隐藏，但本轮不删除后台文字记录、不停止转写、不修改上下文。系统通知、必要告警及非会话页面的文字按原有职责显示。

## 9. 实施与验证边界

实施本界面前已核对小满唤醒、默认实时收音和接入基线。后续继续前仍须读取最新交接，避免覆盖其他会话的补丁、验证记录或运行状态。

按以下顺序验证；已执行部分及待验收项目以验证记录和实施计划为准：

1. 静态状态与素材检查：短文字在圆形屏安全区内，正常和异常状态均可辨认；无字幕挤占光球。
2. 云端固定 SDK 构建：锁定上游和目标 variant，保留现有唤醒、AEC 与播放能力。
3. 实机状态检查：小满唤醒、连接准备、收音、短问答、长回复、插话排空、网络断开/恢复与退出会话。
4. 同机开关对照：相同固件基线下比较动效开/关的收音、Opus、播放、AEC 故障/溢出、内存和语音延迟；不得仅凭浏览器帧率通过验收。
5. 降级检查：降低刷新率及静态回退可以正常工作，不影响既有音频；屏幕熄灭后不继续渲染。
6. 待机与活跃功耗对照：记录相同亮度与使用条件，不在未测量时承诺续航不变。

如果动画引入可感知的卡顿、漏音、插话退化或音频完整性错误，应先关闭/降低动画，再定位原因。语音功能验收独立于视觉偏好，不能以动效好看替代。
