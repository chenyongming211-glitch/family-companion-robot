# 网页设备昵称与位置：补齐真实编辑

用户已确认：复用小程序现有设置能力，在家庭网页和内部后台提供昵称、放置位置编辑；保存后读回确认，三端刷新后一致。沿用此授权直接实施，不重新申请同一范围的设计或发布批准。

## 现有结构与选择

`internal/management/settings.go` 是设置、版本、校验和配置事务的唯一规则入口。小程序已调用家庭 GET/PUT 并再次 GET 核对；两个 Vue 网页只有 RuntimeControls。昵称保存到设备 `display_name`，位置保存到 `location`，原 deviceprofile 中的语音名称不改。

采用同一后端处理器增加 admin scope、同一 Vue 组件服务两端的方案。分别复制后台设置业务规则会造成权限和版本分叉；在网页里复用家庭 Cookie 会破坏后台独立授权。这两种方案不采用。

## 契约及权限

- 两端 GET/PUT `/api/{family|admin}/device-settings/{id}` 使用同一 DTO：`deviceId,name,location,version,canEdit`。PUT 仍严格接受 `name,location,version`。
- 当前账号、当前有效绑定及显式设备授权是读取前提；admin 另外要求 InternalAdmin，写操作再要求对应家庭 CanAddDevices。管理员角色不隐含设备授权或修改权限。
- 配置事务取得写锁后重新核对对应 scope 的会话、账号角色、绑定、授权及版本；版本冲突409、权限不足403。审计保留原请求事件语义，scope 来自真实入口。
- 昵称1至12个 Unicode 码点、位置最多24个码点；trim、控制符和其他后端校验继续由现有规则处理。family wire shape、版本含义和小程序保持兼容。

## 网页职责和交互

`remote-api.ts` 负责作用域请求及响应契约校验；新增最小 settings controller 负责当前设备/请求代次、表单状态和读回确认；共享 DeviceSettings 组件负责显示和事件。权限和持久化仍由 Go 服务负责。

在两个现有设置页的设备选择之后显示普通表单：家庭展示昵称、放置位置、保存、重新读取。保持当前灰白/陶橙样式和手机单列，显示只读权限反馈；不改 RuntimeControls、不增加框架/依赖/弹窗或产品演示数据。

保存只发一次 PUT，再 GET 核对相同设备、name/location/version；匹配后才显示已保存，并刷新当前设备和列表展示。冲突、响应不匹配或网络异常提示重新读取，不自动重发。30秒仍未完成则结果未确认，必须重新读取；迟到结果不得恢复成功提示。请求尚未完成、无权限时禁止重复提交。

切设备、scope、路由、隐藏、退出、401或账号失效时清除草稿/结果并使迟到响应失效；显示后重新读取。表单不保存到 localStorage，不触及音量、亮度、家庭绑定或语音称呼。
