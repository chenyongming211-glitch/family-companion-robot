# 扫码后自动进入配网页面

用户已明确要求：扫码后不再选择附近机器人，直接进入 Wi-Fi 选择、填写密码、点连接的流程。本次沿用已经现场成功的安全配网实现，只减少多余操作。

## 流程与反馈

登录后，唯一有添加权限的家庭自动选中；有多个家庭时先明确选家，再扫描。有效设备码被前台消费一次后自动创建认领、寻找该设备、安全握手、验证任务、扫描网络，随后显示 Wi-Fi 页面。中间显示“正在寻找机器人”“正在验证设备身份”“正在扫描 Wi-Fi”，不展示附近机器人列表，不要求再点发现或点设备。最终按钮为“连接”。设备昵称输入从扫码前移到 Wi-Fi 页面不符合当前接口，故本次移除该非必要输入，使用既有默认命名。

扫码先于登录时，当前前台内存保留已解析设备码，登录成功后按相同规则继续；隐藏、取消、退出、过期、账号变更及旧回调仍执行既有清理，不能悄悄重启旧任务。多个家庭没有明确选择时不自动绑定到第一家。错误明确提示重新扫码，保留取消和网络刷新、手动 SSID。

登录中仅处理一次提交，按钮显示处理中并禁用重复点击，避免较早的登录回调打断后续扫码继续。

## 精确连接与权限

已鉴权的认领创建响应在 waiting 状态新增 `ble_name`，值从可信工厂 MAC 生成 `FAMILY_` 加去冒号的小写 MAC。序列号并不保证包含 MAC，不能从序列号猜测。客户端仅自动连接该名称的服务匹配广播；找不到或多个不同 deviceId 同名时明确失败，不连接列表第一台。广播匹配只是定位，原 Security2 patch1、随机数、设备证明和加密认领校验仍完整执行，密码只在验证通过后加密发送。

重复扫描已确认且属于当前账号/家庭的设备码沿用既有成功分支，不启动蓝牙、不重新供应、不修改原绑定。接口不返回 claim/key 摘要或原始凭据；既有跨家庭、跨账号权限不变。

## 验证和交付边界

新增自动启动一次、隐藏与取消的旧回调、不同目标/重复同名/无目标、确认设备跳过蓝牙、授权响应及无密钥泄漏等测试；全部运行在云端，复核原生构建和官方密码学向量。只更新管理二进制和小程序客户端，不刷新固件、不重启语音、不重置当前微雪、不更改其家庭/绑定起点/正文权限。现场首台新设备体验与代码/合成验证分别记录。
