# 50人公开真人录音：ERes2Net-base扩容评测

日期：2026-11-04。用户明确要求从公开真人录音测试集选50人做大量测试，评估Go＋sherpa-onnx＋ERes2Net-base。执行入口是独立云端实验，直接main提交推送。

## 1. 固定目标与边界

使用当前锁定ERes2Net-base、Go worker和sherpa-onnx-go-linux/v2 v2.0.1，不换模型。评估四件事：50候选人匹配、家庭规模5候选人匹配、原阈值与独立校准阈值的取舍，以及云端CPU／内存／耗时。

现有`evaluate`仅支持3～8人／128片段，在线Tracker最多8个临时标签。本次新增显式`evaluate-large`实验入口，要求恰好50个公开说话人、最多2048片段、2MiB清单；普通evaluate、synthetic benchmark、session阈值和正式服务不变。50人实验不表示在线产品已支持50人。

## 2. 数据与冻结顺序

沿用[3D-Speaker官方测试集](https://3dspeaker.github.io/)，完整归档MD5必须为`45972606dd10d3f7c1c31f27acdfbed7`。只在云端保留有限子集，Mac／Git不接收录音、声纹向量或模型。归档核验并保存来源证明后删除本轮下载的完整大包。

先按归档顺序挑选前50位满足条件的参与者，再运行模型：Device03／Distance00／Dialect00，原始16kHz mono PCM16，每条2～8秒，不切片；每位至少8条不同文字的独立原录音。每人1条登记、3条校准，其余全部作为独立评测（至少4条，最多使用官方可得原句数）。原音频、原录音和规范化文字不跨划分；同一录音的两段不能分别登记与评测。条件或数量不足的参与者在推理前按固定规则跳过并记录原因，不按成绩挑选。

推理前核对官方标签表：Device03为定向麦克风、Device06为PC、Dialect00为普通话；Distance00的物理距离字段为空，不能据此称为近场或填写米数。本轮只作同设备／跨设备条件比较，不作远近距离结论。该模型也来自3D-Speaker体系，本轮为同语料域评测，未独立审计导出权重的训练人物排除情况，不能宣称跨语料泛化或训练零重叠。

优先补Device06／Distance00同句录音作为跨设备对照，缺失时检查Device07；只使用主条件evaluation对应的原句，登记／校准仍使用Device03。核对真实距离标注后再记录跨距离覆盖；覆盖不足明确报告未测，不伪造远场。不同设备的同句属于配对对照，不能重复计为独立语句或额外参与者。

清单沿用public_human来源、匿名fixture编号、官方HTTPS来源、许可参考、source_annotations依据、WAV／原录音／文字摘要、样本数与三划分。Large编号允许fixture_1～fixture_50；普通与合成清单编号约束保留。每人至少1条登记、3条校准、4条评测，未知／缺失／重复／null、路径及摘要错误均拒绝。

## 3. 先固定规则，再打开评测结果

每种数据条件只提取一次特征；特征仅在内存中复用于预先固定的四种规则，报告全部结果，不挑最好一项。登记只用每人的首条合格登记片段，全部合格校准片段形成同人／异人配对；每人缺少合格登记或3条合格校准时报告失败。

| 规则 | 匹配阈值与间距 |
|---|---|
| current_session | 源码现值match=0.682987，margin=0.030229 |
| strict_separation | 沿用全部校准对的同人最小值／异人最大值可分离才评分；不能分离就not_run，不能回退 |
| calibration_far_001 | 仅用校准异人配对选择经验误接纳率不超过0.1%的最小有效阈值；margin固定0.030229 |
| calibration_far_01 | 同上，经验误接纳率不超过1%；margin固定0.030229 |

阈值相等按匹配接纳；为了正确处理边界／同分，取被排除负例边界的`math.Nextafter(score,+Inf)`，并重新统计实际校准误接纳数。若不能在[-1,1]内实现目标，报告不可达。校准的配对误接纳率不等于50候选人的误认率，更不保证评测或家庭现场达到该目标。

评分只使用evaluation。报告50候选人与按匿名编号连续分成10组、每组5候选人的两类结果；小组仍使用同一套冻结规则，不能按评测成绩重分组或重调参数。另报告不使用阈值的Top-1正确数／同分数，帮助区分特征区分能力与拒识政策；Top-1只是诊断，不能当作可直接授予身份的成功。

每项规则记录正确、错误归属、拒识、总量、正确／接纳比例；不合格评测片段计入拒识及总分母。另报告evaluation对登记模板的同人／异人配对接纳／拒绝计数。四项规则、两个候选池复用同一批录音，不把评分次数当独立样本数。

## 4. 资源、工程验证与报告

复用受控子进程特征提取、有界WAV及摘要核验；提取后按原有约定清除向量，取消／错误必须回收worker。报告模型及清单摘要、人数、各划分片段数、音频总时长、长度／能量拒绝、原生推理与IPC时间、冷启动、worker CPU和峰值RSS。主进程峰值单列，不能把不同时刻的RSS峰值相加当并发峰值。所有结果是离线声纹旁路，不代表Qwen／AEC／设备扬声器／真实网络的完整实时延迟。

`human_acceptance`、`production_acceptance`、`feature_enabled`始终false，segmentation／overlap／open_set均unavailable。只输出聚合指标和匿名组号；不输出逐句向量、姓名、文件路径、原文或任意原生错误。报告严格保留校准失败、低质量、覆盖不足和所有预注册规则。

Go／ONNX／数据处理和运行测试全部在云端独立目录；Mac只编辑／Git。源码与云端输入摘要绑定，GOMAXPROCS=2、-p 1，复用既有工具链，不改env／unit／固件／现有模型或阈值，不启动新语音服务。先云端TDD、兼容性回归与独立审查，冻结代码与清单后执行真实50人实验；结果如实记入验证报告并推送main。

## 5. 首轮登记质量失败后的独立补充条件（推理评分前固定）

原始首轮按上述顺序完成并完整保留，不撤回结果：部分首条登记／前三条校准未达到现有RMS≥0.005门禁，全部规则与Top-1按设计为not_run，未产生身份准确率。不能把not_run当0%或挑选阈值重跑。

为完成有效的50人匹配实验，新增明确标记的`qualified-registration-v2`条件，保持同一50人、同一613条主条件原音频及相同模型／代码／全部四规则；只用既有长度／RMS门禁重新划分登记和校准，不参考模型相似度或评测准确率。每人按原归档顺序取前4条达到现有门禁的录音，第1条登记、接下3条校准，其余所有录音均进入evaluation，包含全部低能量录音。每人仍至少4条评测，任何人不够4条合格登记／校准则补充条件失败，不换人。登记与校准的合格要求不用于排除低质量评测，音量不放大、不重采样、不切片。

纯波形检查确认同一50人每人至少6条合格录音，因此无须替换参与者或扩大主录音集合。主条件总数仍613、登记50／校准150／评测413，其中41条低能量录音全部保留为评测拒识。原首轮的特征已清理，未用于补充条件拟合或评分；补充条件各自重新调用同一Go模型，保留两轮全部记录。两轮是相关复测，不增加独立样本数，也不是原始方案一次成功。

跨设备补充条件只取v2 evaluation对应的PC版本，登记／校准用v2主条件的同一200条。缺少的配对录音从官方归档流式取回，完整流重新核对官方MD5并保存实际计算值，不保留完整大包；配对齐全且清单与质量划分经独立检查后才开始v2模型推理。补充条件仍严格禁止根据evaluation调阈值或择优展示。
