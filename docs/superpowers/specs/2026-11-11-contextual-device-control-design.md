# 上下文设备控制：已实现并发布，用户确认通过

用户质疑工具前的关键词意图校验，要求能理解“调大一点”“现在太暗了”，以及刚调暗后反讽“你可真亮啊”。用户已选择“上下文明确时直接小幅调整，有歧义才问一句”。本方案已由8bf101d实现发布，见[验证记录](../../verification/2026-11-11-contextual-device-control.md)；用户于2026-11-11接受现有测试结果并确认本批通过，不再要求额外现场复测；没有新增现场测试证据。

此前实现先用词表和规则筛选，再将本轮转写、已播上下文交给独立无声模型规划固定工具。这保留了引用、否定、其他设备、先读后写等限制，但词表漏项会让模型根本没有理解机会。本批控制规划器仍只收文字，未接收语气音频。

已确认将语义判断交给模型：输入本轮请求、最近已核实的控制动作/已播对话及可用能力，输出不操作/查询/调整/澄清，以及目标字段和方向。上下文与设备返回是数据，不作新授权。明确相对调节先读取新值再计算；精确数值按用户要求；含蓄抱怨在上下文明确时小幅修正，歧义时自然澄清。

服务端保留确定性执行检查：当前已认证设备、工具能力、只读/写入计划一致性、字段与0..100整数范围、相对操作所需新读值、单轮写入次数、取消和过期、实际读回确认。查询计划不得变为设置；未知/失败/取消不能口头声称成功，也不自动重试变更。

| 表达和上下文 | 实现策略 |
| --- | --- |
| 刚调过亮度，用户说“再大一点” | 关联亮度，读当前值后小幅调亮 |
| 当前在调屏幕，用户说“现在太暗了” | 理解为调亮请求 |
| 明确抱怨看不清后又说“你可真亮啊” | 结合负面反馈识别反话并小幅调亮 |
| 无上下文的“你可真亮啊” | 可能夸奖或调侃，轻问是否觉得屏幕太暗 |
| 故事、引用、历史请求、否定或夸人聪明 | 不操作设备 |

接法已收敛：复用既有独立无声文字Native连接，每轮只返回一个`submit_device_control_plan`结构化计划，模型不直接获得硬件设置工具；Go校验完整计划后，经既有Bridge查询/设置及读回。移除正向关键词门槛和多轮模型调硬件路径，不并存两套语义规划器。普通聊天也经过同一模型判断，总语义预算3秒且无重试；最终160次模型尝试148符合场景预期、11次限流和1次截止退出，均未误写，规划p95约1.115秒。主语音、音频与联网配置保持原接法，不预设供应商能混合未经核实的功能。

相对幅度未指定时默认10，由本轮读取的新值计算并限制在0..100；精确数字按明确请求执行，越界拒绝。模型只得到最多4轮当前会话已播对话、最近2条且不超过3轮/5分钟的已核验控制，不拿跨会话记忆或旧数字当新指令/新状态。未核实变更会使相应历史字段失效，取消/清除边界阻止复用。无歧义反馈可小幅修正，歧义则澄清一次；该分支只收转写文字，不承诺识别语音中的所有反讽。

已播对话ID与核验操作turn使用同一会话轮序；较新明确已播主题可覆盖较旧操作字段，新闲聊不产生唯一指代。模型标注当前字段或上下文引用，Go拒绝双字段之后歧义的省略引用。模型保留用户明确数字，不能为符合schema把120截为100；0..100硬约束由Go执行，需要当前数值时先读取设备。

模块职责：Native只负责严格接收一次模型语义计划；Go执行器负责计划、能力、范围、相对算术和完成条件；Bridge继续唯一持有当前设备MCP状态、实际设置与回读。已读/已调结果只作本轮事实给原语音模型。`no_action_issued`根据实际尝试执行的情况生成，不能从错误标签推断，更不能在未知设置后声称“没有改动”。不增加服务、框架、依赖或固件协议。实现/发布以[实施计划](../plans/2026-11-11-contextual-device-control.md)和上述验证记录为准。
