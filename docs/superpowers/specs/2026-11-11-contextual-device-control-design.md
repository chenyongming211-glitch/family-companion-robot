# 上下文设备控制：策略已确认，实施中

用户质疑工具前的关键词意图校验，要求能理解“调大一点”“现在太暗了”，以及刚调暗后反讽“你可真亮啊”。用户已选择“上下文明确时直接小幅调整，有歧义才问一句”。此文记录已确认方向；实现和验证尚未完成前，不表示当前服务已具备反话控制能力。

当前实现先用词表和规则筛选，再将本轮转写、已播上下文交给独立无声模型规划固定工具。这保留了引用、否定、其他设备、先读后写等限制，但词表漏项会让模型根本没有理解机会。控制规划器当前只收文字，未接收语气音频。

建议将语义判断交给模型：输入本轮请求、最近已核实的控制动作/对话及真实设备状态，输出不操作/查询/调整/澄清，以及目标字段和方向。上下文与设备返回是数据，不作新授权。明确相对调节先读取新值再计算；精确数值按用户要求；含蓄抱怨在上下文明确时小幅修正，歧义时自然澄清。

服务端保留确定性执行检查：当前已认证设备、工具能力、只读/写入计划一致性、字段与0..100整数范围、相对操作所需新读值、单轮写入次数、取消和过期、实际读回确认。查询计划不得变为设置；未知/失败/取消不能口头声称成功，也不自动重试变更。

| 表达和上下文 | 建议行为 |
| --- | --- |
| 刚调过亮度，用户说“再大一点” | 关联亮度，读当前值后小幅调亮 |
| 当前在调屏幕，用户说“现在太暗了” | 理解为调亮请求 |
| 明确抱怨看不清后又说“你可真亮啊” | 结合负面反馈识别反话并小幅调亮 |
| 无上下文的“你可真亮啊” | 可能夸奖或调侃，轻问是否觉得屏幕太暗 |
| 故事、引用、历史请求、否定或夸人聪明 | 不操作设备 |

具体接法尚需设计和验证：复用既有模型链路，不预设当前Realtime供应商能同时支持未经核实的音频、工具和联网组合；同时评估普通聊天的额外模型调用、延迟和成本。不得为自然理解额外引入服务/框架，或未经验证移除引用/否定/越权保护。策略选择与实现计划完成后，再以对话场景集、固定执行约束回归和现场回执验收。
