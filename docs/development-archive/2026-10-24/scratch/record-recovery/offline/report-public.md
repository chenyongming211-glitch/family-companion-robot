# 离线断点方法对照：强制对齐与独立输出 ASR（2026-10-23）

结论：两条离线方法均已实际运行，但均未满足自动准确接续条件，生产断点仍为 **unknown**。本轮共保留 **60 次模型推理**：15 个条件 × 2 次重复 × 两种方法。没有采集用户麦克风、连接设备、播放声音、调用付费 ASR、修改生产依赖或加入辅助 ASR。

## 方法、官方来源与边界

A 是既有官方 Qwen3-ForcedAligner-0.6B，输入音频及完整生成稿，直接调用 `Qwen3ForcedAligner.align`。模型 Apache-2.0 许可证见[官方模型卡](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B)；运行方式见[官方仓库](https://github.com/QwenLM/Qwen3-ASR#forcedaligner-usage)。使用原已校验的 ModelScope 快照 `6f4d7c9606feb7adf282c9e4b139f28e8695d867`，权重 SHA-256 为 `47831d0e82f96b20e9034dba01a075ee06436654719f6a68289e49f1b65ce0e7`。沿用前次公开报告所述 80ms 时间戳量化及官方异常时间戳后处理，返回的有序结果不等于声学真值。

B 是官方 **OpenAI Whisper tiny 多语言模型，39M 参数**，直接识别音频，**不提供生成稿或词汇提示**。代码及权重均为 MIT；模型、运行方式与许可证见[官方 README](https://github.com/openai/whisper)。单词时间戳来自 Whisper 自身 cross-attention + DTW，见[固定版本 transcribe.py](https://github.com/openai/whisper/blob/31243bad24cc746f07d4c8bfdd2d974872cb1803/whisper/transcribe.py)及[timing.py](https://github.com/openai/whisper/blob/31243bad24cc746f07d4c8bfdd2d974872cb1803/whisper/timing.py)。它不调用 Qwen 强制对齐器，因此是独立模型候选；它仍不是人工声学真值。

安装版本 `openai-whisper==20250625`，官方 tag commit `31243bad24cc746f07d4c8bfdd2d974872cb1803`。安装的 `__init__.py`、`transcribe.py`、`timing.py`、`tokenizer.py` 与该 commit 官方源文件逐字节一致。`tiny.pt` 为 75,572,083 字节，SHA-256 `65147644a518d12f04e32d6f3b26facc3f8dd46e5390956a9424a650c0ce22b9`，与官方代码中下载 URL 内嵌校验和一致。没有把 Qwen ASR 后接相同 Qwen aligner 的时间戳称作独立验证。

## 独立构造真值

素材全部为机器合成输出。macOS `say -v Tingting -r 150` 分别生成可独立听辨的单位，输出 mono PCM16/16kHz。三个序列为：

- 数数：一至十，各数字单独合成。
- 普通句：`今天阳光很好` / `我们一起去公园` / `然后回家吃晚饭`，各短句单独合成。
- 数字及专有词：`明天下午三点半` / `在上海虹桥站` / `检查OpenStack服务` / `版本二点三`。

每单位使用与被测模型无关的幅值阈值 `abs(sample)>120` 找到合成片段信号支持，加前后 320 帧边距后裁剪；单位之间插入 **0.32 秒静音**，序列开头插入 **0.4 秒静音**。单位起止由拼接帧坐标直接给出。裁剪点是片段的四分之一/二分之一或插入静音中点，不使用任何被测模型的时间戳。恢复样本从第四个单位源坐标开始，第二次在第七个单位中间截断，真值随新文件坐标重置。

这是**人工构造、带静音间隔条件**，不是自然连续语流。这里“完整单位”指完整交付了构造片段；中间截断的音素、部分词实际可辨认程度未知。合成标签来自输入文本，未另经人工逐音审核；对同音专有词尤其不能把合成文本当作人工听辨确认。单位边缘误差是在独立片段支持坐标上的误差，不是经过人工标注的音素边界误差。片段级真值及局限均在私有 manifest 中明确记录。

## 条件与真实结果

以下是**故意不安全的诊断规则**：将模型输出按构造单位匹配，选 `0 < end-start` 且 `end<=当前文件长度` 的最后单位。它用于暴露错漏，不能用于生产接续。匹配单位必须由完整返回 token 拼成，不能切 token 或插值。允许明确的繁简字表、0–50 数字及小数写法转换；保留原始识别文本，并同时记录未经这些转换的 CER。没有把“红桥”修成“虹桥”，没有把同音字修成原稿。

| 条件 | 真值最后完整单位 | A 最后候选 | B 最后候选 | 关键问题 |
|---|---|---|---|---|
| 完整数数 | 十 | 十 | 十 | B 原始识别为阿拉伯数字 |
| 完整普通句 | 第3短句 | 第3短句 | 第3短句 | B 繁体字转换后匹配 |
| 完整数字/专有词 | 第4短句 | 第4短句 | 第4短句 | B 第2短句“虹桥→红桥”，正文覆盖有误 |
| 200ms 开头静音、配完整稿 | 无 | 无 | 无 | A 仍返回十字，十个 span 全部越界；B 空 |
| 第一单位四分之一处取消 | 无 | 无 | 无 | 文件468.375ms；A 返回完整十字，全十 span 越界；B 空 |
| 三之后静音处取消 | 三 | 三 | 三 | A 为四至十造出7个零时长 span |
| 五的片段中间取消 | 四 | **五** | **五** | 两者均把未完整交付的构造片段五当成已完成 |
| 第二短句中间取消 | 第1短句 | 第1短句 | 第1短句 | B 识别部分“我们一起”；不强算部分词 CER |
| 第二短句之后静音取消 | 第2短句 | 第2短句 | 第2短句 | A 为未交付的第三短句返回7个零时长字符 |
| 从四恢复、再次截在七中间 | 六 | **七** | **七** | B 还把四识别成“是”；新文件坐标独立 |
| OpenStack所在第3短句中间取消 | 第2短句 | **第3短句** | **第1短句** | A 构造片段假完成；B “虹桥→红桥”、部分OpenStack识别为“欧盾” |
| 3秒静音、配完整稿 | 无 | **十** | 无 | A 十的0.64–0.80秒正时长 span 属凭空时间戳；B 空 |

12 个构造条件中，诊断最后单位匹配 A **8/12**、B **9/12**；此指标包括静音返回无的情况，不能当作接续成功率。按匹配完整单位集合计算，A 假完成4单位、B 假完成2单位；B 还漏匹配3个真实完整单位（完整专有词第2短句、恢复起始“四”、专有词中断样本第2短句）。A 的零时长条件9/12、越界条件6/12；B 本组没有零时长/越界 span，静音/很早取消的3个条件均为空。这些空结果是正确的拒绝候选，不是异常。两种方法所有成功保留的30次推理均无 Python 推理异常，两次重复的文本和 span 完全相同。

诊断接续影响必须分开理解：五中间取消若从六开始，则跳过五未交付的尾部；再次中断若从八开始，则跳过七未交付的尾部。专有词中断时 A 会跳过第3片段尾部，B 若只凭最后匹配单位从第2片段继续，会重读完整交付过的第2片段。静音时 A 的最后正时长 span 竟是十，忽略前面9个零时长 span 将错误跳过全部原稿。这些是构造片段交付层面的漏尾/重读风险；尚未独立逐音标注，不能据此认定少听了一个完整词。本轮证据不足以声明自动准确接续。

额外保留了被裁剪位置前后50ms的RMS及后续非零采样数，证明截断后仍有合成信号；这些能量诊断不能证明某个词最后音素的位置或可辨认程度。以下“假完成”一律限于构造片段坐标，不能扩大成自然词尾声学结论。

严格生产合同则更保守：不完整音频配完整稿被既有验证器拒绝；零时长/越界/缺覆盖均不能通过；ASR 文字匹配不能替代声学校验。本轮所有物理播放断点仍是 **unknown**。

## 完整样本的独立片段边缘误差

只对3条完整构造序列、能完整匹配且无需拆 token 的单位统计，不使用中断文件填补缺失真值：

| 指标 | A Qwen | B Whisper tiny |
|---|---:|---:|
| 可匹配构造单位 | 17/17 | 16/17 |
| 单位结束绝对误差均值 | 25.8ms | 48.8ms |
| 单位结束绝对误差最大 | 56.5ms | 183.6ms |
| 单位开始绝对误差均值 | 25.8ms | 275.3ms |
| 单位开始绝对误差最大 | 56.5ms | 400ms |

B 常把前导/单位间静音包含在前一个或当前词内，因此起点误差明显大于终点误差。这也说明不能将单个 ASR 时间戳视为真实边界。A 的80ms量化与本次片段坐标恰好较接近，不表示自然语流具备同等精度。

B 完整样本的原始 CER（只去空白/标点、统一大小写）为数数1.10、普通句0.25、数字/专有词0.2581；数字和繁简规范化后分别为0、0、0.03226。数数原始CER可超过1，因为“十”识别为“10”等存在插入。这些是当前合成标签的识别差异，未把词中间截断样本的部分正确输出计作插入错误。

## 复用结果的保守后退诊断

另在现有B输出上评估一条保守策略，不增加模型推理：识别正文经上文同样的显式数字/繁简转换后，必须是完整稿的**唯一、严格文字前缀**；空文本、同音错字或非前缀直接unknown。对通过者找到识别文字涉及的最后一个构造单位，**整个单位留待重读**，只推进到其前面的单位，不用ASR时间戳。

12个构造条件中6个取得构造候选、6个unknown；取得候选的6例均有正向推进，合计推进19个完整构造单位、观察到0个未完整交付单位被推进，同时有4个已经完整交付单位会重读。五中间截断由误推五改为只推进一至四；普通句第二片段中间识别到“我们一起”，最后涉及的第二片段整段后退，保留第一片段推进。再次恢复样本的“是”及专有词的“红桥”不匹配原稿，均unknown。完整数数/普通句及间隙截断也会保守重读最后单位。

这是有限构造集上的无漏尾观测，**不保证任意ASR幻觉前缀仍可靠**，也没有消除自然语流的分词、整段幻觉、同音与采样坐标问题。它展示了用unknown和重读换保守推进的可研究路径；没有改变生产启用门槛，所有设备投影仍unknown。详细规则及每条件列表保留在 `conservative_policy.py` / `conservative-policy.json`。

## 现有真实连续机器人输出

沿用现有 native-provider 24kHz完整数数文件：20.96秒，SHA-256 `8c83603eacd3464a8a7986eaeaad2c09bf4667c65057d7a039149e398463cc3a`。另外跑了43% PCM前缀+完整原稿，以及完整文件+显式转换的中文数字原稿。三条件 × 2重复 × 2方法 =12次，已包含在本轮60次内。

A 原始 `1、2、…、50` 仍合并为一个巨大 token，18.00–20.48秒，无法给单数字位置；43%前缀返回0–0秒巨大 token；完整中文数字条件仍有零时长字符。B 完整音频识别前段为1–25，后面出现20及大量13/14重复，末尾仍输出50；43%前缀还把若干数字合并成12、34、67、91等词。**这是与生成稿的明显不一致，不能把原稿当成已发生声学真值来给ASR准确率，更不能宣称自然语流边界已验证。** 未进行人工边界标注，也未使用A的时间戳给B判分。

## 运行资源与失败排查

## 重现与启用条件

私有工作目录为 `.superpowers/record-recovery/offline/`：`build_fixtures.py`、`manifest.json`、`run_whisper.py`、`score.py`、依赖freeze、原始返回、stderr与来源校验均保留；音频和权重不进Git。构造器重跑TTS可能产生不同字节，必须使用本次manifest源SHA校验，或重新生成manifest后重新测量，不能把旧结果绑定新素材。

```sh
python3 .superpowers/record-recovery/offline/build_fixtures.py
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
.superpowers/resume-state-alignment/venv/bin/python \
  tools/voice-audit/forced_alignment_probe.py \
  --model .superpowers/resume-state-alignment/model \
  --model-revision modelscope:6f4d7c9606feb7adf282c9e4b139f28e8695d867 \
  --manifest .superpowers/record-recovery/offline/manifest.json \
  --output .superpowers/record-recovery/offline/qwen-results.json \
  --device mps --threads 4 --repeats 2
NUMBA_DISABLE_JIT=1 NUMBA_NUM_THREADS=1 OMP_NUM_THREADS=1 \
.superpowers/record-recovery/offline/venv/bin/python \
  .superpowers/record-recovery/offline/run_whisper.py
python3 .superpowers/record-recovery/offline/score.py
```

本次 manifest SHA-256：`99854bd399038299e5e44ff2a0ffb77d478fa494e3608db8f45973f0d73aea0a`。A原始结果SHA：`8dad7a175d8c03bf049888ebeef1b0b5638096e604bed982fe0c5e09306f7303`；B原始结果SHA：`ce73031fd857ef40cce3f51f412fb301ce9d6ab8d46631c7717f9ec23cca3a0c`。评分脚本的规范化是另一个分析层，原始模型结果保持不变。

自动启用仍缺两个同时成立的门槛：①有代表性的自然连续输出需要独立人工/构造覆盖、错误与边界不确定度校验，特别是早取消、同音词、数字、重复及再次中断，且本轮已出现反例；②同一会话/播放身份的源PCM→重采样/编码/队列→设备I2S采样计数映射需要实测标定。本轮只建立离线文件坐标，没有设备映射；I2S交付也不证明用户听到。保留用户明确指定的重新开始点或保守确认，不将其称为测量断点。
