## Cross-cutting checks

1. **Storage ownership, bounds and durability.** `internal/recordstore/store.go:89-100` serializes admission and closure; Save validates and owns its bounded serialized data before enqueueing (`114-141`). Load and Clear share the worker FIFO (`144-201`), and Close stops admission while preserving drain/lock ownership (`206-220`). Initialization secures the dedicated directory and files and rejects invalid snapshots. Raw descriptors are opened with atomic O_CLOEXEC/O_NOFOLLOW (`300-308`). Writes sync the temporary file before rename and then sync the directory, returning failures through receipts (`374-426`). Periodic retention uses the same worker with bounded cadence (`431-454`), so cleanup does not race a second disk writer. The documented inability to interrupt blocked filesystem I/O or guarantee timely cleanup under storage failure is retained.
2. **Per-device isolation and final-save ordering.** `internal/gateway/server.go:199-240` derives the record key from the authenticated normalized MAC, holds a per-device lease across the session and finalization, and rejects a concurrent duplicate. `records.go:425-445` waits for an outstanding clear admission/completion path and submits final state before the lease is released. `server.go:88-115` waits for sessions before closing the store, with a five-second outer shutdown deadline and explicit timeout/failure logging. No session mutation is performed by a disk worker; receipts are consumed by the event loop.
3. **Safe restore and provenance.** `records.go:127-189` makes failed loads write-protected, filters expired/future history, bounds text, clears live playback linkage and restores a new task identity without requesting a response. The restored task retains original/latest source and historical-only sample evidence. `records.go:209-289` prunes individual records/tasks independently of the envelope timestamp; drafts count toward the 128-record bound. History injection excludes interrupted draft text (`history.go:68-81`) and retains the latest 12 entries. The source explicitly separates generated/transport-sent/playback-confirmed/interrupted records, and restored historical playback cannot become current measured position.
4. **Clear authorization and privacy barrier.** `records.go:359-377` requires a complete current known, non-wake, nontruncated explicit deletion command. `records.go:379-423` removes local history/task ownership immediately and dispatches deletion asynchronously; `records.go:322-350` obtains the actual receipt before populating a successful tool result. `clear_native.go:34-93` stops parent playback, empties the audio queue, closes the old socket, increments generation and opens a fresh native conversation without old history. `clear_native.go:138-161` forwards only the authorized current command and subsequent input. The ordinary event-loop generation gate excludes old-socket callbacks. Suppression is scoped to both response and generation and is applied to completion, interruption, snapshot drafts and finalization, including persistence-disabled operation.
5. **New input, cancellation and ACK ordering.** The handshake buffer is limited to 256 events/1 MiB, with abort handled immediately (`clear_native.go:99-123`). Explicit capture cancels stale clear confirmation before replay; committed replacement input cancels it independently (`playback_progress.go:236-250`). Input bytes are owned before crossing the asynchronous boundary; committed audio has already cleared inputTail (`session.go:534-535`). Actual clear results are snapshot data on the fresh socket, not fabricated provider function-call history (`session_tools.go:194-224`). Confirmation tools are explicitly empty and normal tools are restored through the same acknowledged update stream (`generation_sync.go:78-95`, `qwen/client.go:144-150`). `generation_sync.go:97-125` rechecks current input, generation and complete snapshot facts on ACK; an obsolete pending/saved fact cannot release generation. Receipt playback is retired from resumable task ownership (`playback_progress.go:49-51`).
6. **Discard/replacement and recovery scope.** The changes preserve the original routing/unknown-position contract, give new tasks a session namespace and active disposition, and persist user-selected/restart provenance separately from measurements. `generation_sync.go:23-25` makes unavailable tasks and nonexecutable archived history explicit. No auxiliary ASR or automatic exact resume is added to the production path.
