## Important finding

**P2 — An accepted route's pending snapshot ACK can authorize a replacement input before its classification.** `internal/gateway/generation_sync.go:86-103` checks the serialized instructions and settlement state, but does not check the currently active route or the input identity for which the update was sent. `internal/gateway/session.go:486-490` resets sync only when the old route is active. After a route has been accepted and its snapshot update is waiting for ACK, the next `input_audio_buffer.committed` passes through `commitOrigin` (`internal/gateway/playback_progress.go:208-218`), clears the prior decided route, and `requestResponse` starts a new route while retaining the old sync token. If the new transcript has not arrived, neither history nor paused-task snapshot has changed. The old `session.updated` therefore compares equal instructions and sends `response.create` with `route.active=true` and no accepted task binding. That main response subsequently hits the guard at `internal/gateway/session.go:462-463`, interrupting the connection. The source explicitly handles replacement committed inputs, so this transition must fail safely at the generation request itself, independent of whether normal native VAD typically precedes replacement with `speech_started`/reconnect.

Reproduction at exact 5ee source: isolated fake WebSocket test `TestReviewNewInputBeforeAcceptedRouteSnapshotACK`. Accept resume, read its outgoing instructions update without acknowledging it, deliver a different committed item with missing transcript, then deliver the old update ACK. Expected no main output; actual `response.create`. The trace shows old `snapshot_token=1`, replacement input, ACK, then `response_requested` with `task_bound=false`. Test exits 1 in 0.506 s; no native provider or device is involved.
